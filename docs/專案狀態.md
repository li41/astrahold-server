## Protocol v33

v33 延續 v32 warehouse 與既有 equipment contract，不重編 Type125–127；新增 Server-authoritative ammunition selection，並把 bow/crossbow 統一納入箭矢 requirement：

- Type 128 `ClientAmmunitionCommand`：Reliable `select` intent。
- Type 129 `AmmunitionResult`：correlated selected/rejected feedback。
- Type 130 `AmmunitionState`：authoritative manual selection；空值代表木箭 -> 銀箭 automatic。
- Type 125 `ClientWarehouseCommand`：Reliable warehouse intent。
- Type 126 `WarehouseResult`：以 `client_action_sequence` 對應 processed intent。
- Type 127 `WarehouseSnapshot`：完整 replacement snapshot。
- GM warehouse authorization 只信任 Server-authenticated subject `"1"`；Client 不傳 user/account/GM flag。
- map0 warehouse interaction authority 使用正式 `worlds/gm-room/gameplay.json` 的 `stock-keeper` blocker，不要求 `EntityNPC`。
- GM snapshot 兩種強化卷 `quantity=0` 代表 unlimited；Reliable replay 不得重複發物。
- personal warehouse 綁 CharacterID，current character schema v15 要求 initialized warehouse，durable restore 為最終 truth。

v30 裝備強化 contract 仍完整沿用：

- Type 3 `ClientEquipmentCommand`
- Type 111 `EquipmentSnapshot`
- Type119 `ClientEquipmentInstanceCommand`
- Type120 `InventoryInstanceSnapshot`
- Type121 `EquipmentInstanceSnapshot`
- Type122 `AppearanceSnapshot`
- Type123 `ClientEnhanceEquipment`
- Type124 `EquipmentEnhancementResult`

正式七欄固定順序：

```text
main_hand
-> off_hand
-> helmet
-> chest
-> gloves
-> legs
-> boots
```

Type120／121 是 complete replacement snapshot；空集合同樣有清除 stale state 的語義。Type119–122 的 identity 與七欄基礎仍沿用 [Protocol-v29-七欄裝備](Protocol-v29-七欄裝備.md)，v30 不另建第二套 equipment truth。

Type123 只帶 `ScrollItemArchetypeID` 與 exact `ItemInstanceID` intent；Type124 回傳 `enhanced | nochange | broken | rejected`、rejection reason、previous/current enhancement level 與 `ScrollConsumed`。item instance snapshot 的 `enhancement_level` 是 Client 顯示 +N 的 authoritative truth。

弓／十字弓彈藥仍重用既有 inventory/action/combat truth，但 v33 新增 Type128–130 只負責 Server-authoritative 選箭 intent/result/state。

## 裝備／防具／箭矢／強化現況

production catalog 目前共 **107 個可裝備 equipment archetype**：

- 53 武器
- 9 盾牌
- 45 防具

107 不包含箭矢；箭是獨立的可堆疊背包消耗品，不新增第八個裝備欄位。

裝備主材質已收斂為 14 個 stable `MaterialID`；production 107 件以 exact `ItemArchetypeID` 鎖定單一 primary material，catalog validation 拒絕歷史複合／未知材質 ID。正式映射見 [裝備材質規劃](裝備材質規劃.md)。

目前唯一有 gameplay 效果的材質是 `silver`：當玩家 authoritative `main_hand` 是銀質武器、action 是 physical `basic-attack`、目標為 Server-owned `undead` 時，在 raw aggregate 後、critical 前套用 `floor(raw * 1.20)`。銀盾不提供該傷害加成，其他 13 種材質目前沒有隱性倍率。現行正式怪物尚未指定 `undead`，Server 不從名稱或 Client presentation 猜測分類。

### 裝備強化 V1

正式規則見 [裝備強化規劃](裝備強化規劃.md)，Server tracking Issue #199；Client handoff 為 `li41/astrahold-client-three.js#30`。

stable 卷軸：

- `item_astrahold_weapon_enhancement_scroll`：只可用於 weapon。
- `item_astrahold_armor_enhancement_scroll`：可用於 armor 與 shield。

安全值：

- 武器：+6。
- 防具／盾牌：+4。

安全值以下每次合法強化 100% 成功、固定 +1、消耗 1 張卷軸，不會無變化或爆裝。

武器從目前 +6 開始的成功／無變化／爆裝表：

- +6：60/20/20
- +7：50/25/25
- +8：40/30/30
- +9：30/35/35
- +10：20/40/40
- +11：10/45/45
- 目前 >= +12：固定 1/39/60

防具／盾牌從目前 +4 開始：

- +4：60/15/25
- +5：50/20/30
- +6：40/25/35
- +7：30/30/40
- +8：20/35/45
- +9：10/40/50
- 目前 >= +10：固定 1/39/60

**沒有 gameplay 最高強化上限。** 舊 `+10 at_limit` 已移除；尾段仍可用固定 1% 成功率繼續 +1。現在的 `uint16` enhancement level 只是 wire／storage 表示型別，不是 gameplay max；若未來接近表示邊界，應先做資料型別 migration，不能把型別上限變成遊戲規則。

合法嘗試的 Server outcome：

- `enhanced`：消耗 1 卷，保留同一 `ItemInstanceID`，`EnhancementLevel +1`。
- `nochange`：消耗 1 卷，裝備與等級不變。
- `broken`：消耗 1 卷並銷毀 exact target instance；若當時已裝備，同步清空該 equipment slot 並推進 equipment revision。
- `rejected`：不消耗卷軸。

Server 是 RNG 與 mutation owner；Client 不傳 roll／機率／預期結果，也不得 optimistic 扣卷、加 +N 或刪爆裝。可靠 action sequence 在 mutation 前檢查並只接受一次，避免 replay 重複處理。

目前 +N combat stat effect：

- 武器 `+N` -> equipped `PhysicalDamage +N`
- 防具／盾牌 `+N` -> equipped `PhysicalDefense +N`

## 持久化

Server durable inventory 已使用通用 slot encoding 保存七欄 archetype／unique-instance equipment。

unique `ItemInstance.EnhancementLevel` 會走既有 durable instance persistence；成功強化保存新 +N，nochange 不改等級，broken 後 exact instance 不應在後續 durable snapshot／reconnect 還原。

背包 stack 的 durable snapshot 可保存箭矢 stable `ItemArchetypeID` 與數量；射擊扣箭修改正式 inventory truth，並透過既有 inventory replication／persistence 路徑保存。

歷史 `MainHand`／`OffHand`／hand-instance persistence 欄位只作讀取相容；canonicalization 會遷移到通用 equipment encoding。新存檔不以手部專用欄位作 current truth。

character restore 會在 world mutation 前驗證 identity、world identity、角色核心狀態、inventory canonical shape、裝備 legality 與 applicable base-stat requirements；非法 restore fail closed，不以自動脫裝或 derived stat 補足門檻。

### 六大角色屬性／戰鬥

正式 base stats：Strength、Agility、Constitution、Intelligence、Spirit、Charisma；中性基準皆為 10。

已進 live combat：

- effective AGI -> physical hit/evasion
- Strength -> melee production WeaponType basic-attack raw damage bonus
- Agility -> bow／crossbow／sling basic-attack raw damage bonus
- bow basic-attack -> authoritative arrow requirement／consumption＋bow damage＋arrow damage
- crossbow basic-attack -> authoritative arrow requirement／consumption＋crossbow base damage＋arrow damage
- effective AGI -> eligible critical chance
- equipment fixed/affix/set primary stats -> effective primary stats
- weapon enhancement -> equipped PhysicalDamage
- armor/shield enhancement -> equipped PhysicalDefense
- silver main-hand 或實際 fired silver arrow 的 physical basic-attack -> undead raw damage +20%（floor，位於 critical 前；最多套一次）

命中、damage、critical、defense、block、material interaction、箭矢消耗、裝備強化與 skin affinity 最終結果皆由 Server 決定。
