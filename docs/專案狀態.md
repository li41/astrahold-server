## gpt-server 工作分支

gpt-server 對正式 Server 的唯一工作分支是：

**`ai-working-gpt-server`**

不得因 feature、Issue、PR、milestone、Protocol 或 integration task 建立其他 gpt-server Server 工作分支。既有 `gpt-server/*`、`integration/*`、歷史 feature branch 或 archive branch 只能作為歷史證據或比較來源。

## 正式 gameplay authority

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Server 是唯一 gameplay truth。

## P0 Tick / action reentrancy 核對結果

current v27 既有玩家 action producer 都在 world-owner command dispatch 內同步 prepare → resolve；目前 source 沒有獨立反擊、proc、死亡 callback 或其他在 action resolution 中產生巢狀 action 的 gameplay producer。

因此目前不做獨立 reentrancy framework。保留為未來 correctness gate：一旦加入 nested action producer，必須先定義 ordering 並用 focused exactly-once tests 保護，mutation 仍只走 authoritative world-owner path。

## Legacy production E2E validation debt

目前部分舊 production E2E workflow 在 current branch 會失敗，但已確認至少存在以下歷史契約漂移：

- 有 workflow 仍等待 `worldd` 啟動字串中的 `protocol=11`，而正式 Server 已是 v27。
- Production Public Recovery E2E 目前仍嘗試 checkout 已退役的 `li41/astrahold-client`，因此在進入 runtime 驗證前就失敗。

**不得把所有 production E2E failure 一概歸因於同一原因，也不得把這些已知 legacy failure 當成 current gameplay regression 的證據。** 後續應逐 workflow 依 current source / formal Client 更新或退役；在那之前，Server gameplay checkpoint 的 PASS 仍以對應 exact-head Server CI 與真正相關的 focused E2E 為準。

## 目前 active Server 待辦

1. 若 gpt-client 對 #177 回報新的 Server integration blocker，優先解除。
2. Status 下一個具體 gameplay slice 只從 current formal contract 選；沒有完整 ActionID / legality / duration / stack-refresh / derived-state 語義時不自行補數值。
3. 若目前沒有可直接落地的 status contract，改選其他已有正式語義、玩家可見的 PvE / combat slice，不為 roadmap 名稱預建 framework。
4. Legacy production E2E workflow drift 是 validation debt；只在它實際阻塞目前 checkpoint 或需要正式驗證時做 targeted 修復，不讓 infrastructure-first 壓過 gameplay。
5. guild / auction / crafting / siege expansion 等大型 framework 維持後排，除非新的玩家可見需求改變優先順序。
