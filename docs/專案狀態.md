## gpt-server 工作分支

gpt-server 對正式 Server 的唯一工作分支是：

**`ai-working-gpt-server`**

不得因 feature、Issue、PR、milestone、Protocol 或 integration task 建立其他 gpt-server Server 工作分支。

repository 中既有的 `gpt-server/*`、`integration/*`、歷史 feature branch 或 archive branch，只能作為歷史證據、比較來源或保留紀錄；不得再當成 gpt-server 的新工作分支。

## 正式 gameplay authority

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Server 是唯一 gameplay truth。

## 目前 Client integration blocker

### Issue #177 — v27 BrowserWS authoritative target-resource E2E seam

Client 已用真實 `cmd/worldd -network-mode browserws-dev` 驗證 v27 ASTR transport、`SessionWelcome`、Client intent -> Server authoritative rejection 與 disconnect/reset lifecycle。

剩餘 blocker 是：正常 `browserws-dev` 使用 ephemeral identity，不能合法取得 trusted CharacterIdentity / authoritative class，因此 Browser Client 尚不能在真實 BrowserWS 路徑收到 Shadowblade `CharacterTargetResourceState`（type 118）`flaw current > 0` 與對應 clear。

Server 端要求維持：

- normal `browserws-dev` 預設行為不變；
- 不開放 generic trusted authentication 給 BrowserWS；
- 只允許明確啟用、loopback、E2E-only 的 Server-owned bootstrap／harness；
- CharacterIdentity、ClassID、target resource 與 lifecycle clear 仍全部由 Server 決定；
- Protocol 維持 v27，除非真正 wire contract 發生不相容變更。

目前優先完成 Issue #177，再把 exact Server checkpoint 與啟動／操作契約回覆給 gpt-client。

## 下一個 Server gameplay 待辦

### Issue #178 — public ground-drop expiry

Issue #178 已把舊 PR #144 的有效 gameplay requirement 搬回 current-main 語境；不得恢復舊 v20 branch stack。

要求：

- public ground item drop 有 bounded Server-owned lifetime；
- expiry 由單一 world-owner tick path 決定；
- world tick 不做 wall-clock goroutine / blocking I/O；
- pickup / auto-loot / rollback 正確清除 expiry bookkeeping，不能 double mutation；
- expiry 使用正常 authoritative entity lifecycle / `EntityDespawn`；
- deadline arithmetic 不得 wrap；
- 實作必須符合目前 v27 Runtime / loot architecture。

Issue #177 integration blocker 處理完成後，Issue #178 是下一個明確 Server gameplay slice。

## Validation

不得把歷史 PR 的 PASS 直接當成 `ai-working-gpt-server` 新修改的 PASS。

目前 `ai-working-gpt-server` 上的新文件／程式修改在完成對應 CI 前一律視為：

**NOT VALIDATED**

需要宣稱 PASS 時，必須有該 exact head 對應的實際測試／CI 證據。基本 Server gate 仍以 `.github/workflows/server-ci.yml` 為準，包括 `go test ./...`、`go vet ./...` 與 workflow 指定的 race detector package set。

## 歷史資料使用原則

舊 milestone、recovery snapshot、舊 roadmap、舊 PR 與舊 branch 可作為設計／回歸測試證據，但不能覆寫：

1. 使用者最新明確指示；
2. Project Instructions；
3. 正式 Server source / current contract；
4. 正式 repository 現行文件；
5. current PR / Issue。

若歷史文件仍描述已失效的 branch、Protocol、PR 狀態、SHA、blocker 或待辦，gpt-server 可直接整理成歷史敘述或更新為目前狀態，不保留會誤導後續施工的過時資訊。
