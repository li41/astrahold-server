## 核心設計切換：無職業制（Classless）

已確認新的正式遊戲方向：

- 不再以固定職業決定裝備／技能合法性。
- 所有正式技能最終皆可學習。
- 所有裝備原則上皆可使用，只保留真正的裝備類型、欄位、手持衝突與動作需求。
- 角色配裝流派（Build）由屬性配點、裝備、已學技能與實戰配置形成。
- 不再新增新的職業限定遊戲內容。
- authoritative gameplay 與 durable player state 已不再由舊 `ClassID` 決定。現行 v27 `ClientUseAction` 已沒有 `ClassID` 欄位；production initial-class ingress／assignment、fixed-class action authorization、`wrong_class` production rejection，以及 Server 內部 initial-class mutation／enqueue／command dispatch API 都已退役。
- 剩餘 class 相容債主要在 v27 wire：message type 9／115／116、`CharacterClassResourceState` type 117/resource presentation lane，以及 legacy migration／E2E fixture vocabulary。Client #21 的 read-only consumer audit 已完成，正式 Three.js Client 仍主動消費 initial-class intent、type 115／116／117 store/UI 與相關 compatibility semantics；breaking removal 現在被 Client migration／consumer removal 阻塞，不是等待 audit。
- `characterstate.Snapshot` 現在完全 classless；schema v9／save journal v8 不保存 ClassID。舊 v6-v8 character record／v5-v7 journal 的 `class_id` 只在 migration wire decoder 驗證後丟棄，不會恢復成 durable profession truth。
- Resolve、Momentum、Hunt Momentum、Star Heat、Oath Seal 等穩定資源 ID 仍可被既有動作使用，但不是固定職業身分。資源定義 ownership 已開始由 `internal/actionresource` 承接；`internal/classresource` 只保留舊 class 對應與相容入口。

無職業技能組第一版已定為 20 技能：4 通用、4 近戰、4 遠攻、4 法術、4 輔助。

實戰規則：

```text
基本攻擊（basic-attack）
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 6 格自由戰鬥技能（從近戰／遠攻／法術 12 招選）
```

已定數值只有：體魄強健力量 +5、通暢氣脈敏捷 +5、加速術 ×1.3；靈力凝聚確定增加魔法攻擊但數值未定。其他技能數值、冷卻、距離、成長係數與學習方式仍需正式內容決策。

這次設計切換目前**不改 Protocol v27**；移除剩餘 class compatibility messages／semantics 會是另外一次 breaking contract 變更。

## 無職業制伺服器施工狀態

### 20 技能目錄 — 已完成第一個領域基礎

`internal/skillcatalog` 已建立並與舊 `internal/classaction` 完全分離：

- 正式鎖定 20 個穩定技能 ID。
- 五類各 4 招。
- 近戰／遠攻／法術共 12 招可進六格自由戰鬥配置。
- 4 通用 + 4 輔助不占六格。
- 體魄強健、通暢氣脈、靈力凝聚為被動；加速術為主動輔助能力。
- 六格驗證拒絕第 7 招、未知技能、重複技能，以及把固定通用／輔助技能塞入六格。
- 混搭近戰／遠攻／法術合法。

此層只定義技能身分與配置不變條件，不包含傷害、冷卻、取得方式、Protocol 或持久化。

### 六格戰鬥技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/skillloadout` 已建立：

- 以 runtime `EntityID` 擁有六格戰鬥配置。
- 只接受 `skillcatalog` 的合法戰鬥技能組合。
- 保留欄位順序。
- 輸入／輸出皆防止外部 slice 修改污染權威狀態。
- 非法 replacement 不得覆蓋上一份合法配置。
- 支援 authoritative entity lifecycle clear。
- 此 Store 明確是 world-owner mutable state，不自行加入另一套 lock／network authority。
- 非空 `SetCombat` 必須由 authoritative caller 提供已學技能判定；缺少判定或包含未學技能時 fail-closed，上一份合法配置維持不變。
- 空配置仍可直接清除，避免角色編輯／恢復流程被迫發明技能取得語義。

### 六格配置與已學技能持久化 — durable schema 已完成

`internal/characterstate` 的現行 durable contract 已到 character schema v9／save journal v8：

- durable identity 使用 trusted `characteridentity.ID`，不保存 runtime `EntityID`。
- 六格 combat loadout 與 learned skills 都會進入正式 snapshot／save journal，並由 restore/save path 保持 continuity。
- 六格配置必須是已學技能子集；舊 v7 loadout record 在 migration 時只由已配置的正式 combat skills 推導 learned set，不額外發明技能取得內容。
- schema v9 正式移除 durable ClassID；歷史 class wire 只做 migration validation 後丟棄。
- 舊 schema 若夾帶不屬於該版本的新欄位會 fail-closed，不在 migration 中靜默接受不合法資料。

### 已學技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/learnedskills` 已建立：

- 以 runtime `EntityID` 保存角色目前已學會的正式技能集合。
- 接受 20 技能目錄中的任一正式技能，不把六格 combat eligibility 誤當學習限制。
- 拒絕未知技能與重複技能；非法 replacement 不覆蓋上一份合法集合。
- 輸出依正式目錄順序，且不暴露可變內部集合。
- 支援 authoritative entity lifecycle clear。
- 六格 runtime mutation 與已學技能 Store 維持分離；`skillloadout` 只消費 caller 提供的 authoritative membership 判定，因此沒有建立第二套技能取得 authority。

### Action resource classless ownership — 進行中

- `internal/actionresource` 是 Resolve、Momentum、Hunt Momentum、Star Heat、Oath Seal 的通用 definition source。
- `internal/classresource` 保留 alias、legacy fixed-class mapping 與 v27 compatibility adapter；不得再把它當 production profession authority。
- `character.Service` 已提供 classless `GainActionResource`／`SpendActionResource`／`GainActionResourceProgress` owner path；舊 `GainClassResource*` 名稱暫留為相容 wrapper。
- 既有 shipped legacy actions 的資源數值／ID 未因這次重構而改變。
- 後續可逐步把 production call site 與歷史函式名遷移到 action-resource vocabulary；不需等待 Client #21，因為不改 wire。

目前尚未定案的是新的無職業技能取得／學習 Client intent、六格編輯 Protocol、角色屬性 authoritative model 與尚未決定的技能數值；不得為了清技術債自行發明 acquisition 或 build semantics。
