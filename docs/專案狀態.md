## Protocol v29

v29 正式裝備 contract：

- Type 3 `ClientEquipmentCommand`
- Type 111 `EquipmentSnapshot`
- Type119 `ClientEquipmentInstanceCommand`
- Type120 `InventoryInstanceSnapshot`
- Type121 `EquipmentInstanceSnapshot`
- Type122 `AppearanceSnapshot`

正式七欄固定順序：

```text
main_hand
-> off_hand
-> helmet
-> chest
-> gloves
-> legs
-> boots
```

Type120／121 是 complete replacement snapshot；空集合同樣有清除 stale state 的語義。正式契約文件見 [Protocol-v29-七欄裝備](Protocol-v29-七欄裝備.md)。

弓箭彈藥 V1 重用既有 inventory stack 與 action rejection／combat event 路徑，不新增 wire message，因此 Protocol 仍維持 v29。

## 裝備／防具／箭矢現況

production catalog 目前共 **107 個可裝備 equipment archetype**：

- 53 武器
- 9 盾牌
- 45 防具

107 不包含箭矢；箭是獨立的可堆疊背包消耗品，不新增第八個裝備欄位。

裝備主材質已收斂為 14 個 stable `MaterialID`；production 107 件以 exact `ItemArchetypeID` 鎖定單一 primary material，catalog validation 拒絕歷史複合／未知材質 ID。正式映射見 [裝備材質規劃](裝備材質規劃.md)。

目前唯一有 gameplay 效果的材質是 `silver`：當玩家 authoritative `main_hand` 是銀質武器、action 是 physical `basic-attack`、目標為 Server-owned `undead` 時，在 raw aggregate 後、critical 前套用 `floor(raw * 1.20)`。銀盾不提供該傷害加成，其他 13 種材質目前沒有隱性倍率。現行正式怪物尚未指定 `undead`，Server 不從名稱或 Client presentation 猜測分類。

### 弓箭彈藥 V1

正式規則見 [箭矢規劃](箭矢規劃.md)。目前三種 stable 箭矢：

- `item_low_arrow`：木箭，6–8。
- `item_mid_arrow`：鋼箭，8–11。
- `item_high_arrow`：星鋼箭，10–15。

弓本體傷害已拆低：

- `item_hunter_shortbow`：2–3。
- `item_mid_bow`：3–4。
- `item_high_bow`：4–5。

同階弓＋箭仍維持既有總區間 8–11／11–15／14–20。Server 在合併後區間只擲一次傷害。

射擊規則：

- 每次真正成立的弓普通攻擊消耗 1 支箭。
- 未命中仍消耗 1 支。
- 沒箭時 Server 拒絕射擊，不產生傷害／權威射擊結果，也不啟動該次攻擊冷卻；Client 可以只播本地拉弓動畫。
- 目標非法、超距、冷卻中等未成立攻擊不消耗箭。
- 同時持有多種箭時固定由木箭 -> 鋼箭 -> 星鋼箭消耗，避免默默燒掉較稀有箭矢。
- 第一版箭矢不計負重，但仍佔背包 stack。
- 第一版只有 `bow` 使用箭；`crossbow` 不共用箭。
- 第一版沒有銀箭，既有銀武器對不死系 +20% 不自動延伸到箭。

45 件防具分成：

- 15 低階散裝：0 affix、無 set、無 base-stat requirement。
- 15 中階三套：unique `ItemInstanceID`、每件 1 條 Server-rolled affix。
- 15 高階三套：unique `ItemInstanceID`、每件 2 條不同 Server-rolled affix。

六套正式 armor set：

- `set_garrison_steel` 衛戍鋼甲
- `set_windchaser_huntgear` 逐風獵裝
- `set_arcane_rune_robes` 秘紋法衣
- `set_starforged_bastion` 星鑄壁壘
- `set_starshadow_huntgear` 星影追獵
- `set_starlight_robes` 星輝法衣

高階需求：

- 星鑄壁壘：durable base Constitution >= 18
- 星影追獵：durable base Agility >= 18
- 星輝法衣：durable base Intelligence >= 18

requirement 只看角色永久 base stats，不計裝備、affix、set bonus、passive skill、status 等 derived/effective bonus。live equip 與 durable restore 都由 Server 驗證；裝備自己的屬性不能反向滿足自己的穿戴門檻。

套裝 2/5 件 activation 從目前 authoritative equipped pieces 即時計算，不持久化第二份 mutable set-active state。fixed modifiers、unique affixes、set bonuses 共用 authoritative equipment stat aggregation。

unique 裝備 archetype 與 exact instance 都會透過正式 owner snapshots 複寫 Client state；Client 不得依 UI index 或 optimistic local equipment state 決定 gameplay。

## 持久化

Server durable inventory 已使用通用 slot encoding 保存七欄 archetype／unique-instance equipment。

背包 stack 的 durable snapshot 可保存箭矢 stable `ItemArchetypeID` 與數量；射擊扣箭修改正式 inventory truth，並透過既有 inventory replication／persistence 路徑保存。

歷史 `MainHand`／`OffHand`／hand-instance persistence 欄位只作讀取相容；canonicalization 會遷移到通用 equipment encoding。新存檔不以手部專用欄位作 current truth。

character restore 會在 world mutation 前驗證 identity、world identity、角色核心狀態、inventory canonical shape、裝備 legality 與 applicable base-stat requirements；非法 restore fail closed，不以自動脫裝或 derived stat 補足門檻。

## 現行 gameplay truth

### 無職業角色／技能

- fixed class 不再決定裝備／技能合法性。
- durable character state 不保存 `ClassID`。
- generic action resource 由 `internal/actionresource` 擁有；production policy 由 `internal/actionpolicy` 擁有。
- 20 個 stable SkillID、authoritative learned-skill state、6 格 combat loadout 與 durable persistence 已存在。
- 技能取得／學習、忘卻／重置、六格編輯產品語義仍未定；Server 不自行發明。

### 六大角色屬性／戰鬥

正式 base stats：Strength、Agility、Constitution、Intelligence、Spirit、Charisma；中性基準皆為 10。

已進 live combat：

- effective AGI -> physical hit/evasion
- Strength -> melee production WeaponType basic-attack raw damage bonus
- Agility -> bow／crossbow／sling basic-attack raw damage bonus
- bow basic-attack -> authoritative arrow requirement／consumption＋bow damage＋arrow damage
- effective AGI -> eligible critical chance
- equipment fixed/affix/set primary stats -> effective primary stats
- silver main-hand physical basic-attack -> undead raw damage +20%（floor，位於 critical 前）

命中、damage、critical、defense、block、material interaction、箭矢消耗與 skin affinity 最終結果皆由 Server 決定。

### 遭遇／掉落／生命週期

- damage-driven threat V1 已存在。
- invalid target／despawn／defeat／leave／respawn／leash 有 cleanup path。
- ground drop 有 authoritative bounded TTL。
- pickup／autopickup／expiry／rollback 共用 authoritative lifecycle。
- defeated character 不得 pickup／equip／unequip。
- generic transient-status lifecycle foundation 已存在。

## 地圖 authority

Client 仍主導 layout／visual scene／assets；Server 只承接已 handoff 的 gameplay facts。

目前 Server 已納入：

- 第一大陸 authoritative movement envelope：X `-2600..2600`、Z `-900..4100`。
- 12 個地表 Region core polygon。
- 9 個地下 map authority entry；有精確 envelope 的地下空間保存正式 envelope，其餘只保存 Client 已定義的 authority metadata，不捏造未定 geometry。

Client terrain tile、render padding、scene node、asset path、visual collider 不會自動成為 Server gameplay truth。
