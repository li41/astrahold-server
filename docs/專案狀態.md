## 核心設計切換：無職業制（Classless）

已確認新的正式遊戲方向：

- 不再以固定職業決定裝備／技能合法性。
- 所有正式技能最終皆可學習。
- 所有裝備原則上皆可使用，只保留真正的裝備類型、欄位、手持衝突與動作需求。
- 角色配裝流派（Build）由屬性配點、裝備、已學技能與實戰配置形成。
- 不再新增新的職業限定遊戲內容。
- authoritative gameplay 與 durable player state 已不再由舊 `ClassID` 決定；v27 `ClientUseAction.ClassID` 僅保留為 wire compatibility，待正式 Client #21 完成 consumer audit 後才能做 breaking Protocol removal。

無職業技能組第一版已定為 20 技能：4 通用、4 近戰、4 遠攻、4 法術、4 輔助。

實戰規則：

```text
基本攻擊（basic-attack）
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 6 格自由戰鬥技能（從近戰／遠攻／法術 12 招選）
```

已定數值只有：體魄強健力量 +5、通暢氣脈敏捷 +5、加速術 ×1.3；靈力凝聚確定增加魔法攻擊但數值未定。其他技能數值、冷卻、距離、成長係數與學習方式仍需正式內容決策。

這次設計切換目前**不改 Protocol v27**。

## 無職業制伺服器施工狀態

### 20 技能目錄 — 已完成第一個領域基礎

`internal/skillcatalog` 已建立並與舊 `internal/classaction` 完全分離：

- 正式鎖定 20 個穩定技能 ID。
- 五類各 4 招。
- 近戰／遠攻／法術共 12 招可進六格自由戰鬥配置。
- 4 通用 + 4 輔助不占六格。
- 體魄強健、通暢氣脈、靈力凝聚為被動；加速術為主動輔助能力。
- 六格驗證拒絕第 7 招、未知技能、重複技能，以及把固定通用／輔助技能塞入六格。
- 混搭近戰／遠攻／法術合法。

此層只定義技能身分與配置不變條件，不包含傷害、冷卻、取得方式、Protocol 或持久化。

### 六格戰鬥技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/skillloadout` 已建立：

- 以 runtime `EntityID` 擁有六格戰鬥配置。
- 只接受 `skillcatalog` 的合法戰鬥技能組合。
- 保留欄位順序。
- 輸入／輸出皆防止外部 slice 修改污染權威狀態。
- 非法 replacement 不得覆蓋上一份合法配置。
- 支援 authoritative entity lifecycle clear。
- 此 Store 明確是 world-owner mutable state，不自行加入另一套 lock／network authority。
- 非空 `SetCombat` 必須由 authoritative caller 提供已學技能判定；缺少判定或包含未學技能時 fail-closed，上一份合法配置維持不變。
- 空配置仍可直接清除，避免角色編輯／恢復流程被迫發明技能取得語義。

### 六格配置持久化 — 已完成 durable schema 第一版

`internal/characterstate` 已把六格配置納入 durable character state：

- character state schema 已升至 v7；save journal 已升至 v6。
- durable identity 使用 trusted `characteridentity.ID`，不保存 runtime `EntityID`。
- 舊 character state v6／journal v5 可安全遷移為空六格配置。
- 舊 schema 若夾帶新 `combat_loadout` 欄位會 fail-closed，不會在 migration 中靜默丟資料。
- 新 schema 會拒絕未知、重複、非戰鬥技能與非 canonical slot。
- save journal 與正式 snapshot 同步保存六格配置，避免 crash replay 遺失配置。

### 已學技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/learnedskills` 已建立：

- 以 runtime `EntityID` 保存角色目前已學會的正式技能集合。
- 接受 20 技能目錄中的任一正式技能，不把六格 combat eligibility 誤當學習限制。
- 拒絕未知技能與重複技能；非法 replacement 不覆蓋上一份合法集合。
- 輸出依正式目錄順序，且不暴露可變內部集合。
- 支援 authoritative entity lifecycle clear。
- 此層不決定技能取得方式、預設已學技能、持久化、Protocol 或網路複寫。

六格 runtime mutation 與已學技能 Store 維持分離；`skillloadout` 只消費 caller 提供的 authoritative membership 判定，因此沒有建立第二套技能取得 authority。

目前尚未把新的無職業已學技能／六格配置接到 Client intent 或 Protocol；已學技能 durable migration、角色屬性模型與 worldruntime restore/save／legality wiring 仍待後續分層完成。

## 近期伺服器順序

1. 無職業 20 技能目錄、六格執行期狀態、六格 durable schema、已學技能執行期狀態，以及「六格必須為已學技能子集」的 runtime mutation gate 已完成第一版基礎。
2. 下一步評估角色屬性的 authoritative model；只使用已正式定案的屬性概念，不自行發明完整主屬性清單、配點總量、每級點數、洗點方式或未定數值。
3. 再評估已學技能 durable schema／migration；舊角色的預設已學集合與技能取得方式未定，不得為了持久化自行發明 acquisition semantics，也不得讓既有合法六格配置在 migration 中被靜默破壞。
4. 後續接 worldruntime restore/save、實際動作 legality 與必要 Protocol；Server correctness 不等待 Client。
5. 持續既有權威正確性 audit，優先戰鬥、掉落、背包、裝備、遭遇生命週期。
6. v27 `ClientUseAction.ClassID` 僅剩 wire compatibility debt；等待 Client #21 consumer audit，Server 不單方面做 breaking removal。
