## 核心設計切換：無職業制（Classless）

已確認新的正式遊戲方向：

- 不再以固定職業決定裝備／技能合法性。
- 所有正式技能最終皆可學習。
- 所有裝備原則上皆可使用，只保留真正的裝備類型、欄位、手持衝突與動作需求。
- 角色配裝流派（Build）由屬性配點、裝備、已學技能與實戰配置形成。
- 不再新增新的職業限定遊戲內容。
- authoritative gameplay 與 durable player state 已不再由舊 `ClassID` 決定。現行 v28 `ClientUseAction` 沒有 `ClassID` 欄位；production initial-class ingress／assignment、fixed-class action authorization、`wrong_class` production rejection，以及 Server 內部 initial-class mutation／enqueue／command dispatch API 都已退役。
- 剩餘 class 相容債主要在 legacy wire message type 9／115／116、`CharacterClassResourceState` type 117/resource presentation lane，以及必要 legacy migration／E2E fixture vocabulary。Client #21 的 read-only consumer audit 已完成，正式 Three.js Client 仍主動消費相關 compatibility semantics；breaking removal 由 Client migration／consumer removal 阻塞，不因 Protocol 已升 v28 而自動刪除。
- `characterstate.Snapshot` 現行為 character schema v13／save journal v12，完全不保存 `ClassID`；v13/v12 新增的是 durable `SkinID`。durable ClassID 自 schema v9／journal v8 起已退役。舊 v6-v8 character record／v5-v7 journal 的 `class_id` 只在 migration wire decoder 驗證後丟棄，不會恢復成 durable profession truth。
- `CharacterRestore.LegacyRuntimeClassID` 與 `internal/classresource` source compatibility package 均已退役；現行 runtime 不再需要 class-to-resource lookup。歷史 `class_id` decoder 仍是舊存檔 fail-closed migration boundary，不屬於可直接刪除的 gameplay 技術債。
- Resolve、Momentum、Hunt Momentum、Star Heat、Oath Seal 等穩定資源 ID 仍可被既有動作使用，但不是固定職業身分。資源定義 ownership 由 `internal/actionresource` 承接；production policy 由 `internal/actionpolicy` 擁有。Type117 的 class 命名只存在 legacy Protocol presentation compatibility 邊界。

無職業技能組第一版已定為 20 技能：4 通用、4 近戰、4 遠攻、4 法術、4 輔助。

實戰規則：

```text
基本攻擊（basic-attack）
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 6 格自由戰鬥技能（從近戰／遠攻／法術 12 招選）
```

已定技能數值包含：體魄強健力量 +5、通暢氣脈敏捷 +5、加速術 ×1.3；靈力凝聚確定增加魔法攻擊但數值未定。角色屬性本身已正式定為力量、敏捷、體質、智力、精神、魅力六項，基礎值皆為 10；完整成長規劃與衍生公式見 [角色屬性與成長規劃](角色屬性與成長規劃.md)。技能傷害、冷卻、距離與多數個別技能係數仍需依正式內容規格逐步落地。

六屬性 foundation 本身當時沒有改 wire；現行 Protocol 升到 v28 的原因是 unique-item instance 與 appearance contract。未來創角 10 點配置、51 級後配點與 Client 可見屬性同步若需要新 intent／state message，仍必須先由 Server 定義正式 contract。

## 無職業制伺服器施工狀態

### 20 技能目錄 — 已完成第一個領域基礎

`internal/skillcatalog` 已建立，並與 legacy action policy ownership 完全分離：

- 正式鎖定 20 個穩定技能 ID。
- 五類各 4 招。
- 近戰／遠攻／法術共 12 招可進六格自由戰鬥配置。
- 4 通用 + 4 輔助不占六格。
- 體魄強健、通暢氣脈、靈力凝聚為被動；加速術為主動輔助能力。
- 六格驗證拒絕第 7 招、未知技能、重複技能，以及把固定通用／輔助技能塞入六格。
- 混搭近戰／遠攻／法術合法。

此層只定義技能身分與配置不變條件，不包含傷害、冷卻、取得方式、Protocol 或持久化。

### 六格戰鬥技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/skillloadout` 已建立：

- 以 runtime `EntityID` 擁有六格戰鬥配置。
- 只接受 `skillcatalog` 的合法戰鬥技能組合。
- 保留欄位順序。
- 輸入／輸出皆防止外部 slice 修改污染權威狀態。
- 非法 replacement 不得覆蓋上一份合法配置。
- 支援 authoritative entity lifecycle clear。
- 此 Store 明確是 world-owner mutable state，不自行加入另一套 lock／network authority。
- 非空 `SetCombat` 必須由 authoritative caller 提供已學技能判定；缺少判定或包含未學技能時 fail-closed，上一份合法配置維持不變。
- 空配置仍可直接清除，避免角色編輯／恢復流程被迫發明技能取得語義。

### 六格配置、已學技能、六屬性與外觀持久化 — durable schema 已完成

`internal/characterstate` 的現行 durable contract 已到 character schema v13／save journal v12：

- durable identity 使用 trusted `characteridentity.ID`，不保存 runtime `EntityID`。
- 六格 combat loadout、learned skills、六大基礎屬性與 selected `SkinID` 都會進入正式 snapshot／save journal，並由 restore/save path 保持 continuity。
- 六格配置必須是已學技能子集；舊 v7 loadout record 在 migration 時只由已配置的正式 combat skills 推導 learned set，不額外發明技能取得內容。
- schema v9 正式移除 durable ClassID；歷史 class wire 只做 migration validation 後丟棄。
- schema v11／journal v10 是短暫的力量／敏捷雙屬性過渡格式；schema v12／journal v11 正式擴成六屬性；現行 v13／journal v12 再加入 `SkinID`。舊版本若夾帶不屬於該版本的新欄位會 fail-closed。
- schema v1-v10 沒有六屬性欄位，遷移時六屬性皆使用正式中性基準 10；不會從舊職業或其他欄位推導配點。
- schema v1-v12 沒有正式 appearance 欄位，遷移到 v13 時 selected skin 為 `appearance.None`；不從 asset path、UUID 或其他欄位猜皮膚。
- 現行 durable base 屬性每項不得低於 10；沒有自行發明終身上限。

### 已學技能執行期狀態 — 已完成第一個權威狀態基礎

`internal/learnedskills` 已建立：

- 以 runtime `EntityID` 保存角色目前已學會的正式技能集合。
- 接受 20 技能目錄中的任一正式技能，不把六格 combat eligibility 誤當學習限制。
- 拒絕未知技能與重複技能；非法 replacement 不覆蓋上一份合法集合。
- 輸出依正式目錄順序，且不暴露可變內部集合。
- 支援 authoritative entity lifecycle clear。
- 六格 runtime mutation 與已學技能 Store 維持分離；`skillloadout` 只消費 caller 提供的 authoritative membership 判定，因此沒有建立第二套技能取得 authority。

### 六大角色屬性 — Server authority／durable foundation 已完成，部分公式已進 live combat

- `internal/characterstats` 現行正式主屬性為力量、敏捷、體質、智力、精神、魅力六項；正式中性基準皆為 10。
- `character.State.PrimaryStats` 保存 authoritative base values；learned passive skill bonus 不重複寫入 durable state。
- 體魄強健 +5 力量、通暢氣脈 +5 敏捷由 learned-skill truth 即時計算；靈力凝聚與加速術未定部分不自行補數值。
- `worldruntime` 已有單一唯讀 effective-primary-stats seam，從 base stats + learned passives 得出最終六屬性，不建立第二套 mutable stat store。
- physical `basic-attack` 命中已使用 attacker effective AGI 的 `PhysicalHitModifier`、target effective AGI 的 `EvasionModifier`、武器 accuracy 與 unique-equipment hit/evasion；公式為 `clamp(90% + (totalHit-totalEvasion)*0.5 percentage points, 75%, 98%)`。miss 不造成傷害但會 commit cooldown。
- melee basic-attack raw damage 已依 `WeaponTypeDefinition.BasicAttackDamageAttribute` 接入 Strength bonus；現行 production `one_hand_sword`、`one_hand_axe`、`mace` 明確 authored 為 Strength。Agility ranged-damage seam 已存在，但 production `bow/crossbow/sling` 尚未有正式武器 item／damage classification，不自行把未落地內容當完成。
- eligible damage critical chance 已接 effective AGI：base 5%，AGI > 30 每完整 +10 AGI 增加 1 percentage point，另加 `CriticalRating * 0.5pp`，上限 30%。
- 其餘已定純公式 helper（例如 INT magic-power、CON HP、SPI MP、CHA leadership）仍只在有正式 owner/formula 的 feature 才可接入；不得因 helper 存在就自行改現行技能傷害或建立第二套 level truth。
- 正式規劃中的創角額外 10 點、單項創角最多 +5、51 級後每級 +1 點尚未接 runtime mutation，因目前 Server 尚無獨立正式 character-level/progression owner。

### Action resource classless ownership — Server 內部 generic 化已完成

- `internal/actionresource` 是 Resolve、Momentum、Hunt Momentum、Star Heat、Oath Seal 的通用 definition source。
- `internal/actionpolicy` 是現行 production action/resource policy owner；既有 legacy class-named ActionID 只保留為穩定內容識別，不代表固定職業授權。舊 `internal/classaction` package 已退役且不保留 alias shim。
- `internal/classresource` package 已退役，不再保留 alias 或 fixed-class resource lookup；production 與 Server 內部相容 caller 都直接使用 generic action-resource vocabulary。
- `character.Service` 的可呼叫 resource mutation owner path 已只保留 `GainActionResource`／`SpendActionResource`／`GainActionResourceProgress`；舊 `GainClassResource*` wrapper 已退役。
- `character.State` 已使用 `ActionResourceID`／`ActionResourceCurrent`／`MaxActionResource`／`ActionResourceProgress`；通用 runtime state 不再暴露 `ClassResource*` 欄位。外部 production caller 優先透過 `State.ActionResource()` 取得 immutable generic read view。
- production worldruntime 的 resource cost／gain／progress／accepted-reduction 與 target-resource policy lookup 已改由 `internal/actionpolicy` + generic owner path 負責；舊 `validate/consume/apply...ClassResource` worldruntime shim 已退役。
- `CharacterRestore` 已完全 classless；`LegacyRuntimeClassID` 欄位與其驗證／fixture 已退役。歷史 profession identity 只在 persistence migration decoder 驗證後丟棄，不進 gameplay restore payload。
- class-aware inventory restore shim 已退役；durable inventory restore 不再接收或忽略假 `ClassID` 參數，裝備合法性只看實際 item／slot。
- Type117 legacy class-resource feedback 與 Type118 target-resource feedback 的共用 bounded Reliable delivery使用 generic `pendingResourceMessages`／`maxPendingResourceMessagesPerSession`／`trySendResourceMessage`／`retryPendingResourceMessages`；只有 Type117 Protocol adapter 保留 class-resource wire 名稱。兩種 resource feedback 每個 `Runtime.Step` 都只在開頭 retry 一次，inventory replication 不再同 tick 重複 retry。
- 已有 regression test 保護持續 backpressure 時「每 tick 僅一次 resource retry」；ownership transfer 也會清除舊 session 的共用 resource delivery state，不把 legacy profession truth 帶入新 session。
- loadbot 的 `network_errors` 已補最多 8 筆 bounded `{bot_index, stage, error}` 診斷樣本；既有 aggregate count、`network_errors=0` hard gate 與 UDP shutdown correlation 行為不變。成功報告不輸出額外欄位。
- `internal/character` 與 action-policy 的一般資源測試已直接使用 `actionresource` vocabulary；Type117／legacy Protocol 測試仍保留 class 名稱，因為那裡是真正相容邊界。
- 既有 shipped legacy actions 的 ActionID、資源數值與 target-resource tiers 未因 ownership 重構而改變。
- 剩餘 class compatibility 技術債集中在 message type 9／115／116／117、`wrong_class` vocabulary 與必要 persistence migration／E2E fixture。涉及 breaking wire removal 的部分必須等 Client #21 完成 migration，不得由 Server 單方面刪除或重新編號。

目前尚未定案／未落地的是新的無職業技能取得／學習 Client intent、六格編輯 Protocol、正式角色等級 owner、創角／51 級後屬性點 mutation contract，以及尚未決定的個別技能數值；不得為了清技術債自行發明 acquisition、level 或 build semantics。

## 現行遊戲事實

### Physical basic-attack 命中／爆擊／屬性

現行 Server physical `basic-attack` 已啟用：

```text
HitChance = clamp(90% + (totalHit - totalEvasion) * 0.5 percentage points, 75%, 98%)
```

`totalHit` 由 attacker effective AGI、武器 accuracy 與 authoritative unique-equipment hit bonus 組成；`totalEvasion` 由 target effective AGI 與 authoritative unique-equipment evasion 組成。Server 擲命中；miss 不扣 HP、仍 commit cooldown 並發出權威結果。

現行 melee production WeaponType 的 `basic-attack` raw damage 已吃 Strength bonus；eligible damage 的 critical chance 已吃 effective AGI，critical multiplier 與後續 defense/block/self-mitigation 仍由既有 incoming-damage owner path處理。

### 裝備／unique instance／外觀 affinity

已有 5 把低階武器、3 面盾牌、主手／副手、武器傷害／命中、盾牌減傷／格擋／魔法減傷、裝備持久化。

攻速正式規則為 `WeaponType -> BasicAttackIntervalMS`：相同武器類型共用同一基礎攻速，單件 `ItemArchetype` 不得覆寫。`equipmentcatalog.Weapon` 只保存 `WeaponType` 與武器戰鬥資料；`CatalogDefinition.WeaponTypes` 是唯一基礎攻速 ownership table，strict loader 會拒絕舊 per-item `basic_attack_interval_ms`。18 類 V1 正式基礎節奏已定案：空手由 `basic-attack` 使用 600ms，17 個裝備武器類型均已 authored；完整表與 authority 邊界見 [武器攻速](武器攻速.md)。Client 只消費 Server `cooldown_ready_tick` 的最終有效節奏，不從本地表或動畫決定 gameplay outcome。
