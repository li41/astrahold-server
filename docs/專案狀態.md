## 正式 gameplay authority

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Server 是唯一 gameplay truth。

- consume Protocol v23

Server 不修改 Client source。

## 目前內容討論狀態

### 盾牌已確認

- block roll 由 Server 做
- 成功才套 `BlockReduction`
- v1 不看 facing / front arc
- 低階盾全職業可用
- 高品質盾未來可以限制職業
- `PhysicalDefense` 換算公式尚未定案
- blockable damage categories 尚需正式鎖定

### 吸魔武器已確認方向

- 不固定 +5 MP
- 不可無限吸同一目標
- 應與目標 MP／可吸額度相關
- 數值需有隨機變化

完整公式、取得方式、武器內容仍未定。

## 近期排序

1. 先完成盾牌 authoritative defense / block / magic reduction 設計與單一 incoming-damage pipeline。
2. 補 encounter threat table / target fallback consistency。
3. 建 generic status / buff / debuff lifecycle。
4. 用少量 monster abilities 增加 PvE encounter 差異。
5. 再往 item instance、economy transaction、party、quest 推進。
6. guild / auction / crafting / siege 等大型 framework 維持後排。

## Validation debt

部分 historical production E2E 仍可能包含舊 Protocol / 舊 Client assumptions。

處理原則：

- 不隱藏紅燈。
- feature head 與 exact base head 做同型比較。
- base 已失敗才標記 pre-existing debt。
- 新 regression 不得以歷史債務為理由忽略。
- 真的影響 gameplay authority、data integrity、security、persistence correctness 的 failure 必須阻擋。

驗證規則見 [驗證規範](驗證規範.md)。
