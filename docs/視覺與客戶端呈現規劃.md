# 星壘 — 視覺與客戶端呈現規劃

本文件整理原 `astrahold-assets/docs/visual-direction/` 中仍適用於目前正式 **Three.js Client** 的產品方向。

舊 Unreal-only 實作細節，例如 UMG、Niagara、Lumen、Paragon、Manny/Quinn、Unreal Engine 特定材質／燈光參數，不再視為現行規劃。

## 一、產品視覺定位

### 暗色邊境奇幻

世界應呈現：

- 寒冷、磨損、資源不足的邊境感
- 木、鐵、布、泥土、灰燼等 grounded material
- 魔法是少量、受控制的視覺重點
- 不做滿畫面霓虹或全身發光

### 風格

目標是 **stylized realism**：

- 比寫實略強化 silhouette 與 gameplay readability
- 不走 anime / cartoon
- 不追求 photoreal clutter
- 不做明顯模仿 Lineage、Diablo、Lost Ark、WoW 等既有遊戲的 public identity

## 二、Gameplay camera 下的可讀性

所有角色、怪物、裝備、VFX、場景都應從實際遊玩 camera 評估，而不是只看正面資產展示。

目前方向維持高角度 2.5D / 俯視閱讀：

- 上表面輪廓很重要：肩膀、背部、武器、盾牌、狼的頭背尾、屋頂與地面路徑。
- 玩家、NPC、敵人必須只看 silhouette 就能區分。
- 小型裝飾不能遮掉戰鬥 entity。
- Client camera 是 presentation；target legality、range、LOS、movement 不得由 camera 決定。

## 三、玩家、NPC、怪物的最低呈現標準

### 玩家

- 真正可動畫 humanoid presentation。
- idle / walk / run / basic attack 至少能完整呈現。
- 主手／副手裝備要明顯改變 silhouette。
- 不以 debug mannequin / placeholder 當 final public identity。

### NPC

- 重要 NPC 必須和玩家 silhouette 區分。
- 名牌與互動狀態要明確，但不要像 debug text。
- Client 只呈現 Server 的 NPC lifecycle / interaction state。

### 怪物

以 Grayridge Wolf 類 quadruped 為目前閱讀標準：

- idle / move / attack / hit / defeated 狀態清楚。
- 從 gameplay camera 能看清頭、身體、尾巴與移動方向。
- `Server ActionStarted` 才能觸發 authoritative attack presentation。
- `CombatEvent` / Vitals 改變驅動 hit feedback。
- `defeated=true` 驅動 defeated presentation。
- `EntityDespawn` 才是最終 lifecycle removal。

死亡動畫播完不能自行刪除 Server entity。

## 四、Emberwatch 起始區的場景方向

原 Assets 規劃中有效的核心不是 Unreal 場景座標，而是玩家動線與構圖：

```text
玩家出生
-> 可讀的道路／入口
-> Warden / NPC 崗位
-> 營火與補給 focal point
-> 營地出口
-> 附近第一個怪物 encounter
```

場景應：

- 是緊湊的邊境營地，而不是大型城市。
- 有明確道路與地面材質差異。
- 有營火、帳篷／棚架、圍籬、補給箱、桶、岩石、植被等一致場景語彙。
- 用樹牆、岩壁、霧化或其他 presentation 手段處理視覺邊界。
- 不保留大型 debug 圓盤／競技場地板／primitive cube/cylinder 作 final scenery。
- 不因視覺場景方便而自行改 Server movement / collision / LOS truth。

如果場景 geometry 會影響 movement legality、navigation、LOS、combat range、spawn、objective，就必須有 Server-owned gameplay representation。

## 五、色彩與材質方向

### 地面／環境

- 草：偏 muted olive，可混乾草。
- 泥土／道路：比草略暖、略亮，幫助導航。
- 岩石：偏冷灰。
- 木材：weathered brown，有新舊差異。
- 布料：褪色 neutral / ochre；重要 faction 可用 charcoal + ember accent。
- 鐵：深色粗糙金屬，少量鏽蝕。
- 火焰：場景最強暖色 focal point。

### 魔法 accent

- 主要暖色 accent 採 ember orange 系。
- 每個 subject 只保留少量明確魔法重點。
- 不做滿身 glow。

## 六、戰鬥資訊呈現

玩家必須立即看懂以下五個狀態：

```text
selected
attack started
hit landed
 defeated
loot spawned
```

最低呈現：

- selected target ring / outline / ground indicator
- target HP
- attack animation
- hit reaction 或短促 hit VFX
- defeated state
- loot marker

Server combat 即使數值正確，如果玩家看不出「有沒有打到」，仍不算商用品質。

## 七、盾牌呈現

盾牌 gameplay 結果由 Server 決定。

Client 需要呈現的資訊：

- OffHand 裝備模型／icon
- Server 判定 block 成功時的 block animation / VFX / SFX
- 最終 authoritative damage number / Vitals state

Client 不得：

- 自己擲 BlockChance
- 用角色 facing / local raycast 自己判斷 block
- 因盾牌動畫碰到攻擊就自行減傷

## 八、UI 方向

### 基本風格

- compact dark-fantasy MMORPG UI
- charcoal / dark neutral panels
- aged brass / ember accent
- 不要過度 ornate
- 避免滿畫面金框、符文 glow、手機遊戲式 neon

### 繁中優先

- 繁體中文是預設第一優先語系。
- 字型必須有完整 zh-Hant glyph coverage。
- 不能出現 tofu / missing glyph。
- 數字與 stable ID 仍可使用 Latin / digit 字形。

### 最低 HUD

- 玩家 HP / MP
- target name + HP
- compact world nameplate
- inventory / equipment
- NPC interaction / shop
- loot / pickup feedback

### Equipment UI

至少能清楚顯示：

- MainHand
- OffHand
- 裝備資格提示
- Server authoritative equipment snapshot

UI 不自行重算裝備傷害、防禦、重量、格擋或職業資格。

## 九、VFX 方向

VFX 是 feedback，不是 gameplay authority。

最低種類：

- basic melee hit
- monster hit
- defeated feedback
- target indicator
- loot marker
- pickup feedback
- campfire / environment ambience effect
- shield block success feedback

規則：

- damage VFX 由 Server-confirmed combat result 觸發。
- cosmetic weapon trail / footstep dust 可以由 animation timing 驅動，但不能造成 damage。
- loot marker 隨 Server drop entity lifecycle 出現／消失。

## 十、Audio 方向

最低需要：

- player footsteps
- weapon swing
- weapon hit
- monster attack / hurt / defeated
- shield block
- loot pickup
- UI click / rejection
- campfire ambience

Audio playback 不決定 hit、damage、HP、death、block 或 entity lifecycle。

## 十一、目前最高視覺優先順序

舊 Assets Top-10 經 Three.js 現況整理後，保留以下產品排序：

1. 移除 debug arena / primitive residue，建立真正地面與路徑。
2. 讓第一批怪物在 gameplay camera 下讀得像真正 animated creature。
3. target / attack / hit / defeated / loot feedback 完整。
4. 建立緊湊 Emberwatch 場景 composition。
5. 補足 foliage / rocks / scene boundary dressing。
6. world labels 換成 compact 繁中 MMORPG presentation。
7. 主手／副手裝備模型與 silhouette 對應 Server equipment truth。
8. 加入營火與一致的材質／光影語彙。
9. 補 loot marker / pickup feedback。
10. 補最小 combat / world audio。

## 十二、效能與商用品質原則

- 不依賴特定 vendor upscaler 才能正常遊玩。
- 大型資產進 Client 前要做裁切、LOD / level-of-detail 或其他 Three.js 適用優化。
- presentation improvement 必須以實際 gameplay camera / runtime 衡量。
- 不為了漂亮 screenshot 破壞 Server authority 或 runtime correctness。
