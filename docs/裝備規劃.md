# 星壘 — 裝備規劃

本文件記錄正式 Server 的裝備內容規劃。Server 是唯一 gameplay authority；Client 只消費權威裝備狀態與事件，不得自行決定裝備合法性、傷害、屬性需求、套裝效果、攻速、命中、格擋或其他 gameplay 結果。

本文件中的 `ItemArchetypeID`、裝備欄位、需求、基礎數值與套裝效果，均作為正式 Server 規劃依據；Client 模型、動畫、圖示與資產路徑不屬於 gameplay identity。

### 投石正式方向

「投石」不是投石索，也不是另一種弓類武器。角色就是直接拿石頭丟出去，主要目的是增加遊戲趣味與世界互動感。

正式規劃如下：

- 低階：小石頭
- 中階：中石頭
- 高階：大石頭
- 三者共用相同基礎攻擊間隔：1100ms
- 三者普攻傷害都看力量，不看敏捷
- 石頭大小只影響傷害與重量，不改變攻速
- 投石不應成為高階最佳遠程輸出解；其傷害預算應低於同階正式遠程武器主線
- Server 現行舊識別若仍使用 `sling`，後續實作應改成不帶「投石索」語義的正式投石識別，例如 `thrown_stone`

### 「晨星」名稱修正

原先 `morning_star` 的中文「晨星」辨識度太低，不作為正式玩家顯示名稱。

第一版依實際美術外型採下列其中一種：

- 若是柄、鏈條、帶刺鐵球：正式中文名稱使用「鏈錘」。
- 若是固定柄直接連接帶刺頭部：正式中文名稱使用「狼牙錘」。

在美術外型最終確認前，Server 穩定識別仍可維持既有 `WeaponType`，但文件與玩家顯示不得把「晨星」當作已定案的正式中文名稱。

若最終採鏈錘方向，三階名稱暫定：

- 低階：鐵鏈錘
- 中階：精鋼鏈錘
- 高階：星刺鏈錘

- 高階：2 條且同一件物品不得重複相同詞綴

武器與盾牌沿用正式 Server 現有詞綴規則。

新增防具後，防具詞綴池規劃為：

- 力量
- 敏捷
- 智力
- 體質
- 精神
- 魅力
- 物理命中
- 爆擊值
- 閃避
- 最大生命
- 最大魔力
- 物理防禦
- 魔法防禦
- 法術威力

防具不產生固定物理傷害詞綴，避免五件高階防具的雙詞綴把純物理傷害堆疊過快。

## 十、套裝權威規則

套裝效果由 Server 根據當前實際穿戴的 `ItemArchetypeID`／`SetID` 即時計算。

不得持久化第二份可變的「套裝效果已啟用」真相。登入、換裝、卸裝、死亡／重生需要重建有效裝備狀態時，都從實際裝備重新計算。

第一版只使用：

- 2 件效果
- 5 件效果

不建立 3 件或 4 件效果，以保留無職業混裝與混合流派空間。

## 十一、正式實作前需要補齊的 Server 通用能力

107 件內容進正式 catalog 前，需要先完成下列通用系統：

1. 五個防具欄位：頭、胸、手、腿、足。
2. 單手／雙手權威佔用規則；雙手武器不得與盾牌同時合法裝備。
3. 高階裝備永久基礎屬性需求驗證。
4. 防具固定屬性資料結構。
5. 防具隨機詞綴種類。
6. `SetID` 與 2 件／5 件套裝效果的 Server 重算路徑。
7. 投石的正式 `WeaponType` 語義從舊 `sling` 名稱收斂為直接投擲石頭，不引入投石索。
8. 遠程基本攻擊距離與合法性由 Server 定義，Client raycast 不得決定命中。

上述能力應做成通用裝備系統，不得為單一物品或單一套裝複製 gameplay 邏輯。
