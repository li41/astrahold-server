# 星壘 Astrahold — 無職業技能系統規劃

> 本文件是角色 Build、技能池與技能配置的正式現行規劃。舊職業技能／ClassID 設計不得覆寫本文件；現有 class-era Server 實作只視為遷移中的 legacy contract。

## 一、核心方向

Astrahold 不再以固定職業決定角色能穿什麼、能學什麼或能使用什麼技能。

角色 Build 由以下組合形成：

```text
屬性配點
+ 裝備
+ 已學技能
+ 實戰技能配置
= 玩家 Build
```

正式原則：

- 沒有 gameplay-authoritative 固定職業。
- 所有角色最終都可學習全部正式技能；技能取得／學習方式尚未定案。
- 所有裝備原則上對所有角色開放；只保留物品本身真正需要的 slot、手持衝突、裝備類型等非職業限制。
- 技能強弱由正式的屬性 scaling、裝備與技能本身規則決定，而不是由 ClassID 決定合法性。
- 舊 Oathguard、Breaker、Ranger、Shadowblade、Starfire 等名稱若未來保留，只能作為推薦 Build／教學 archetype，不是 Server gameplay identity。
- 不再新增新的 class-gated action、class-only equipment 或 class-specific gameplay resource。

## 二、實戰技能配置

正式 V1 配置：

```text
basic-attack
+ 4 個通用技能：全部可用，不占 6 格
+ 4 個輔助技能：全部可用，不占 6 格
+ 6 個自由戰鬥技能：從近戰／遠攻／法術共 12 招中選 6 招
```

6 個自由戰鬥技能可以跨分類任意混搭，例如近戰 + 法術、遠攻 + 法術、近戰 + 遠攻都合法。

通用與輔助技能不是「第 7～14 個自由技能槽」；它們屬於角色固定可用能力，不消耗六格 Build 選擇。

## 三、Classless Skill Set V1 — 20 技能

### A. 通用技能 4

全部角色可用，不占六個自由戰鬥技能槽。

| # | 技能 | 現行定位 | 尚待定案 |
|---|---|---|---|
| 1 | 瞬間移動術 | Server 選擇並驗證隨機合法位置後瞬移 | 隨機範圍、安全落點規則、CD／成本 |
| 2 | 日光術 | 通用能力 | 正式 gameplay 效果、CD／成本 |
| 3 | 防禦 Guard | 短時間防禦能力 | 減傷、持續時間、CD／成本 |
| 4 | 治癒術 | 瞬間恢復生命 | 恢復量、scaling、CD／成本 |

`瞬間移動術` 的最終位置必須由 Server authoritative navigation / legality 決定，Client 不得自行選一個隨機位置後直接成立。

### B. 近戰技能 4

從本組與遠攻／法術共 12 招中自由選入六格。

| # | 技能 | V1 身分 |
|---|---|---|
| 5 | 重擊 Heavy Strike | 高衝擊單體近戰 |
| 6 | 連斬 Flurry | 快速多段近戰 |
| 7 | 橫掃 Cleave | 近距離多目標／範圍攻擊 |
| 8 | 處決 Execute | 對低生命目標具有收尾價值 |

精確傷害、武器 requirement、range、cooldown、resource、scaling 尚未定案，不從舊職業技能直接繼承數值。

### C. 遠攻技能 4

| # | 技能 | V1 身分 |
|---|---|---|
| 9 | 穿透射擊 Piercing Shot | 高衝擊遠程攻擊／穿透或破防方向 |
| 10 | 快速射擊 Rapid Shot | 快速持續遠程輸出 |
| 11 | 箭雨 Volley | 指定區域遠程 AoE |
| 12 | 牽制射擊 Pinning Shot | 傷害 + 移動牽制方向 |

需要弓／弩／其他 ranged weapon 時，應以技能本身的 equipment requirement 表達，而不是職業限制。穿透／破防與 slow 的精確公式尚未定案。

### D. 法術技能 4

| # | 技能 | V1 身分 |
|---|---|---|
| 13 | 火焰彈 Fire Bolt | 直接單體魔法攻擊 |
| 14 | 冰霜爆發 Frost Burst | 範圍魔法 + 控制方向 |
| 15 | 隕星 Meteor | 延遲／高衝擊範圍魔法 |
| 16 | 奧術長矛 Arcane Lance | 強力單體／穿透方向魔法 |

精確傷害、range、cast/cooldown、資源、控制時間、defense interaction 與 scaling 尚未定案。

### E. 輔助技能 4

全部角色可用，不占六個自由戰鬥技能槽。

| # | 技能 | 類型 | 已定案效果 |
|---|---|---|---|
| 17 | 體魄強健 | 被動 | 力量 +5 |
| 18 | 通暢氣脈 | 被動 | 敏捷 +5 |
| 19 | 靈力凝聚 | 被動 | 增加魔法攻擊；精確加成尚待定案 |
| 20 | 加速術 | 主動 | x1.3；影響項目、持續時間、CD／成本尚待定案 |

前三個輔助技能在學會後屬於被動能力；`加速術` 是固定可用主動輔助技能，但不占六格。

## 四、屬性與技能強度

目前只把已明確討論的概念列為正式方向：

- 力量：存在角色配點／戰鬥 scaling 的設計空間；`體魄強健` 明確提供力量 +5。
- 敏捷：存在角色配點／戰鬥 scaling 的設計空間；`通暢氣脈` 明確提供敏捷 +5。
- 魔法攻擊：正式戰鬥衍生值／能力概念；`靈力凝聚` 會提高它，但數值尚未定案。

目前**沒有**正式定案完整主屬性清單、配點上限、每級點數、洗點方式或各技能 coefficient。不得把舊職業屬性或先前討論中未確認的 Power／Vitality／Focus 自動帶入正式規格。

技能未來的強度模型遵守：

```text
技能本身效果
+ 正式屬性 scaling
+ authoritative equipment effect
= Server 最終 gameplay result
```

同一技能人人可學，但不同配點與裝備會形成不同強度與 Build。

## 五、裝備規則

目標模型是 classless equipment legality：

- Server 驗證物品 ownership、slot、MainHand / OffHand 衝突與技能真正需要的 equipment tag。
- 不以固定職業決定一般裝備能否使用。
- 目前既有低階裝備本來就是 `ClassPolicy=All`，可平順過渡。
- legacy `ClassPolicy=AllowList` / ClassID 限制不再是未來裝備設計方向。

## 六、Gameplay resource 原則

舊 class resource 不自動延續為新系統。

未來若某技能需要資源，資源應屬於技能／mechanic 的正式規則，而不是因角色宣告某個 ClassID 才存在。

現有 Resolve、Momentum、Hunt Momentum、Flaw 等 class-era mechanics 在完成遷移前仍可能存在於 runtime；它們只是 legacy compatibility / migration debt，不代表新的 20 技能必須繼承相同資源。

## 七、Server authority

所有技能一律維持：

```text
Client Intent
-> Server 驗證已學技能／配置／裝備／目標／距離／LOS／資源／CD
-> Server 決定命中、傷害、治療、狀態、移動與最終位置
-> Authoritative State / Events
-> Client Presentation
```

特別是隨機傳送、傷害 roll、治療量、加速、控制效果都不能由 Client 決定 gameplay outcome。

## 八、Legacy migration

目前正式 Server v27 仍有 ClassID、class-gated actions、class resource 與舊技能 contract。它們不會因規劃切換就直接刪除，避免破壞現有 Protocol／persistence／regression correctness。

遷移順序：

1. 停止新增新的 class-gated gameplay。
2. 建立 classless character attribute / learned-skill / loadout 的 authoritative model。
3. 建立 6 格自由戰鬥技能配置與通用／輔助固定能力規則。
4. 以新 20 技能逐步取代舊職業 action catalog；不自動搬舊數值。
5. 將裝備 legality 從 ClassID policy 收斂為 classless equipment requirements。
6. 處理 legacy class resource 與 persistence migration。
7. 只有在 current Protocol / durable state 不再依賴 ClassID 後，才移除對應 legacy contract。

任何一步需要 Protocol change 時，先以 Server formal contract 定義 semantics，再交由 Client 消費；Client 進度不阻塞其他 Server-only gameplay slice。

## 九、尚待內容決策

以下目前刻意保持未定，不得自行補數值：

- 瞬間移動術的隨機半徑／合法落點政策。
- 日光術的正式效果。
- Guard 的減傷與時間。
- 治癒術的瞬間恢復量。
- 靈力凝聚的魔法攻擊加成。
- 加速術的 x1.3 套用對象、持續時間與 CD。
- 12 個自由戰鬥技能的傷害、CD、range、cost、scaling、equipment requirements。
- 技能取得／學習方式。
- 配點總量、成長、重置方式。
- classless gameplay resource 的最終模型。

這些內容等正式討論定案後再進 Server，不從 legacy class skill 數值或 `myriad-throne-server` 直接複製。
