# 星壘 Astrahold — 無職業技能系統規劃

本文件記錄已確認的 **classless character / skill direction**。這是後續角色、技能、裝備與配點系統的內容規劃；現行 Server source / Protocol 尚未完成遷移前，既有 `ClassID`、class-gated action、class resource 仍是目前 runtime truth，不得為了符合本規劃而直接破壞既有 authoritative contract。

當舊的「持續擴張固定職業專屬技能」方向與本文件衝突時，後續新內容以本文件為準：**停止新增新的 class-gated gameplay，改往無職業 Build 系統遷移。**

## 一、核心方向：沒有固定職業，只有 Build

角色不再由固定職業決定能穿什麼、能學什麼、能施放什麼。

正式方向：

- **所有裝備都可以使用**；未來不以職業作為 equipment legality gate。
- **所有技能都可以學習**；技能分類只是玩法分類，不是職業。
- **配點決定技能強度**；同一招技能由不同配點、裝備與搭配產生不同效益。
- 玩家可以混合近戰、遠攻、法術與輔助技能，自行形成 Build。
- 裝備需求可以存在，但必須是動作本身合理的 requirement，例如射擊需要遠程武器、防禦技能若未來要求盾牌則由 equipment tag 決定，不能重新包裝成職業限制。
- Client 只送 intent 與呈現結果；技能 legality、屬性、裝備、資源、傷害、治療、buff、傳送位置都由 Server authoritative 決定。

現有 `class_oathguard`、`class_breaker`、`class_ranger`、`class_shadowblade`、`class_starfire` 等身份，後續可以降級為推薦 Build / 歷史相容標記，但不再作為新 gameplay expansion 的核心身份。

## 二、第一版技能池：20 招

第一版技能池固定規劃為：

```text
4 通用
4 近戰
4 遠攻
4 法術
4 輔助
= 20 招
```

`basic-attack` 是基礎攻擊，不計入上述 20 招。

玩家最終可以學習跨分類技能；同時可以配置幾個主動技能、技能學習成本與重置方式尚未定案，不在此階段自行補數值。

## 三、通用技能（4）

### 1. 瞬間移動術

定位：機動／脫離／重新站位。

- 發動後傳送到**隨機位置**。
- 隨機目的地由 Server 決定，Client 不得提供最終座標。
- Server 必須驗證目的地可站立、合法且不穿越 gameplay collision authority。
- 隨機範圍、是否受 LOS 影響、能否跨越障礙、冷卻與資源消耗尚未定案。

### 2. 日光術

定位：通用法術／功能型技能。

- 技能名稱與第一版技能槽位已確認。
- 實際 gameplay 效果、範圍、持續時間、資源消耗與 scaling **尚未定案**。
- 不因名稱自行推導傷害、治療、照明、驅散或對特定怪物加成。

### 3. 防禦 Guard

定位：通用生存技能。

- 主動進入短時間防禦狀態。
- 具體減傷率、持續時間、冷卻、資源成本與是否受裝備影響尚未定案。
- 最終 incoming damage 必須繼續走 Server authoritative defensive resolution，不得由 Client 自行套減傷。

### 4. 治癒術

定位：通用即時恢復。

- **瞬間恢復 HP**。
- 恢復量、scaling、冷卻與資源消耗尚未定案。
- Server 決定合法目標與最終恢復量；Client 不自行修改 HP。

## 四、近戰技能（4）

### 1. 重擊 Heavy Strike

- 單體重型近戰攻擊。
- 傷害高、節奏較慢。
- 主要受近戰武器與相關配點影響。
- 精確傷害公式、倍率與 cooldown 尚未定案。

### 2. 連斬 Flurry

- 快速多段近戰攻擊。
- 偏向敏捷、快速武器與持續輸出 Build。
- 每段傷害、段數、攻擊間隔與資源成本尚未定案。

### 3. 橫掃 Cleave

- 近距離範圍攻擊。
- 攻擊角色前方多個合法目標。
- 範圍、最大目標數、傷害 scaling 與 cooldown 尚未定案。

### 4. 處決 Execute

- 單體收尾技能。
- 目標低生命時效果提高。
- 低血量門檻、額外效果與 scaling 尚未定案。

## 五、遠攻技能（4）

遠攻技能不是 Ranger 職業技能。需要弓、弩或其他遠程武器的技能，以正式 equipment requirement 驗證，而不是 `ClassID`。

### 1. 穿透射擊 Piercing Shot

- 強力單體遠程攻擊。
- 具部分防禦穿透方向。
- 穿透比例、武器 requirement、傷害與 cooldown 尚未定案。

### 2. 快速射擊 Rapid Shot

- 短時間快速連續遠程攻擊。
- 偏向敏捷與快速遠程武器 Build。
- 射擊次數、間隔、每發傷害與資源成本尚未定案。

### 3. 箭雨 Volley

- 指定區域的遠程 AoE。
- Server 決定合法目標、命中與每次 authoritative damage。
- 範圍、持續時間、命中次數與傷害尚未定案。

### 4. 牽制射擊 Pinning Shot

- 遠程傷害兼控制。
- 方向為降低目標移動能力。
- slow 比例、持續時間、stack / refresh policy、傷害與 cooldown 尚未定案。

## 六、法術技能（4）

法術不是 Mage / Starfire 職業專屬技能。任何角色都可以學習，強度由配點、裝備與正式 scaling 決定。

### 1. 火焰彈 Fire Bolt

- 快速單體魔法傷害。
- 定位為穩定直接輸出。
- 傷害、施法時間、資源成本與 scaling 尚未定案。

### 2. 冰霜爆發 Frost Burst

- 範圍魔法傷害兼移動控制。
- slow 數值、範圍、持續時間與傷害尚未定案。

### 3. 隕星 Meteor

- 延遲生效的重型範圍魔法攻擊。
- cast / telegraph / impact 都由 Server authoritative timing 驅動。
- 延遲、半徑、傷害與資源成本尚未定案。

### 4. 奧術長矛 Arcane Lance

- 高單體魔法爆發。
- 具有穿透／破防方向，但第一版精確 defensive semantics 尚未定案。
- 不在 contract 完成前自行套用 armor ignore 或 resistance ignore。

## 七、輔助技能（4）

### 1. 體魄強健

- 效果：**力量 +5**。
- 暫定為持續型／被動輔助效果；最終裝備／學習／啟用模型在 implementation contract 時鎖定。
- Strength 的完整 derived-stat 影響與 stacking policy 尚未定案。

### 2. 通暢氣脈

- 效果：**敏捷 +5**。
- 暫定為持續型／被動輔助效果；最終裝備／學習／啟用模型在 implementation contract 時鎖定。
- Agility 的完整 derived-stat 影響與 stacking policy 尚未定案。

### 3. 靈力凝聚

- 名稱：**靈力凝聚**。
- 效果：**提升魔法攻擊**。
- 魔法攻擊增加量／倍率尚未定案，不自行假設為 +5。
- 暫定為持續型／被動輔助效果；MagicAttack 的正式 base / derived / stacking formula 之後再定。

### 4. 加速術

- 效果倍率：**x1.3**。
- 由 Server authoritative buff / derived-state 決定倍率與有效期。
- x1.3 具體作用於移動速度、攻擊速度、施法速度或其中哪些項目 **尚未定案**，在正式 contract 前不得自行擴張。
- 持續時間、cooldown、資源消耗與 stacking policy 尚未定案。

## 八、配點與技能強度

已確認原則：**不是用配點決定能不能學，而是用配點決定學了之後有多強。**

因此未來 skill definition 應朝這類結構發展：

```text
Base Effect
+ Attribute Scaling
+ Equipment Scaling
+ Skill-specific mechanic
```

而不是：

```text
RequiredClassID -> 能用 / 不能用
```

目前只確認「力量」、「敏捷」與「魔法攻擊」已會出現在第一批輔助效果中；完整屬性集合、每點屬性的影響、技能 scaling coefficient、soft cap / hard cap 都尚未正式定案。

## 九、裝備使用方向

Classless 方向下：

- 所有正式裝備都對所有角色開放。
- Server 仍驗證 item ownership、equipment slot、主副手衝突與正式 equipment requirement。
- 不新增新的 `ClassPolicy=AllowList` 內容。
- 現有 `ClassPolicy` / `AllowedClassIDs` 可暫時作為相容資料存在，但應視為待遷移 legacy gate，而不是未來設計方向。
- 未來若有屬性需求、等級需求、雙手武器規則等，必須另外正式討論，不得用職業限制替代。

## 十、現有職業技能的遷移原則

現有正式 Server 已經有一批 class-specific action、class resource 與測試。這些不能一次刪除，否則會破壞 current runtime correctness。

遷移原則：

1. **停止新增新的 class-gated skill。**
2. 先建立 classless attribute / learned-skill / action-loadout 所需的 Server-owned foundation。
3. 將仍值得保留的舊技能 mechanic 映射到上述 20 招；沒有必要保留的同質技能直接淘汰，不為每個舊職業維持一套重複技能。
4. `Resolve`、`Momentum`、`Hunt Momentum`、`Flaw` 等舊 class resource 不因歷史存在就自動永久保留。
5. 若某個 resource mechanic 值得留下，應改成技能／Build mechanic，而不是職業身份本身。
6. 等 classless legality、learned skills、配點與必要 persistence 都有測試保護後，再移除 gameplay `RequiredClassID` / class gate。
7. Protocol 是否需要調整，由真正的 Client-visible contract 需求決定；不能為了重命名概念就無必要升版。

## 十一、第一階段 Server 施工順序

這次規劃先鎖定方向，不代表以下項目已實作。

建議實作順序：

```text
1. Classless attribute / derived-stat model
2. LearnedSkills durable authority
3. Skill legality 不再依賴職業身份
4. Equipment legality 移除未來 class restriction path
5. 將現有 actions 收斂／映射成 Classless Skill Set V1
6. 將值得保留的 resource mechanic 從 class identity 解耦
7. Action loadout / 同時可配置技能數量
8. persistence / reconnect / death / respawn lifecycle regression
9. 最後才退休不再需要的 ClassID gameplay gates
```

每個 slice 都必須保持：

```text
Client Intent
-> Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Client 進度不作為 Server foundation 的阻塞條件；但任何 Client-visible Protocol change 仍要留下正式 contract / integration handoff。

## 十二、目前仍待討論

以下內容尚未定案：

- 日光術實際效果。
- 瞬間移動術的隨機範圍與合法目的地規則細節。
- Guard 的減傷率、持續時間、cooldown。
- 治癒術的瞬間恢復量與 scaling。
- 靈力凝聚的魔法攻擊增加量／倍率。
- 加速術 x1.3 到底影響哪些速度，以及持續時間／stacking。
- 完整角色屬性集合與配點上限。
- 20 招的完整數值、資源成本、cooldown、range、AoE、scaling coefficient。
- 玩家可以學會多少技能、同時可以配置多少主動技能。
- 技能學習來源、重置／洗點方式與經濟成本。

未定內容在正式討論前不得由 agent 自行補完。
