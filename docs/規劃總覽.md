## 固定遊戲權威

```text
客戶端意圖（Client Intent）
-> Go 伺服器驗證／決策（Validate / Decide）
-> 權威狀態／事件（Authoritative State / Events）
-> 客戶端呈現（Client Presentation）
```

伺服器是唯一遊戲事實來源。客戶端動畫、特效（VFX）、介面（UI）、鏡頭、預測、根運動（root motion）、射線檢測（raycast）、平滑處理不得決定遊戲結果。

## 核心角色設計：無職業制

Astrahold 的正式未來方向已改為 **無職業配裝流派系統（Classless Build System）**：

```text
屬性配點
+ 裝備
+ 已學技能
+ 實戰技能配置
= 玩家配裝流派（Build）
```

- 固定職業不再決定裝備或技能合法性。
- 所有裝備原則上皆可使用，只保留物品／動作本身真正需要的非職業限制。
- 所有正式技能最終皆可學習。
- 舊職業名稱最多作為推薦配裝流派，不是遊戲權威身分。
- 不再新增新的職業限定動作、職業限定物品或職業專屬資源。
- 現有 v27 `ClassID`／職業限定執行期邏輯仍屬舊制遷移技術債；在通訊協定／持久化安全遷移前不直接拔除。

### 無職業技能組第一版（Classless Skill Set V1）

技能池先固定收斂為 20 招：

```text
通用 4：瞬間移動術、日光術、防禦（Guard）、治癒術
近戰 4：重擊（Heavy Strike）、連斬（Flurry）、橫掃（Cleave）、處決（Execute）
遠攻 4：穿透射擊（Piercing Shot）、快速射擊（Rapid Shot）、箭雨（Volley）、牽制射擊（Pinning Shot）
法術 4：火焰彈（Fire Bolt）、冰霜爆發（Frost Burst）、隕星（Meteor）、奧術長矛（Arcane Lance）
輔助 4：體魄強健、通暢氣脈、靈力凝聚、加速術
```

實戰配置：

```text
基本攻擊（basic-attack）
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 從近戰／遠攻／法術 12 招中自由選 6 招
```

其中體魄強健 = 力量 +5、通暢氣脈 = 敏捷 +5、靈力凝聚增加魔法攻擊（數值待定）、加速術 = ×1.3（作用項目／持續時間／冷卻時間待定）。完整規格見 [無職業技能系統規劃](無職業技能系統規劃.md)。

## 現在的可玩主線

優先把 MMORPG 基本循環做成值得玩的產品：

```text
移動
-> 選怪
-> 攻擊／被攻擊
-> 生命／魔力（HP / MP）／冷卻時間
-> 死亡／重生
-> 擊殺
-> 掉落
-> 撿取
-> 背包
-> 使用物品
-> 裝備
-> 配裝流派／技能
-> 持久化
```

客戶端新手村進度不再作為伺服器遊戲施工門檻；只在通訊協定消費／執行期整合真正需要時留下整合 Issue。

## 已完成的伺服器遊戲基礎

### 低階武器／裝備第一版

目前有 5 把低階主手、3 面盾牌、主手／副手（MainHand／OffHand）、武器體型傷害、攻速、伺服器權威命中、盾牌物防／格擋／魔法減傷與裝備持久化。

低階裝備目前**尚無正式取得方式**；沒有怪物掉落、掉率、商店、材料兌換、任務、製作、初始裝備或價格。不得自行補經濟內容。

### 武器命中第一版

低階武器對實體目標的 `basic-attack`：

```text
HitChance = clamp(90 + accuracy_modifier * 2, 75, 98)
```

伺服器擲 0..99 命中值；未命中（miss）不扣生命、產生權威未命中結果，且攻擊冷卻時間仍成立。

### 盾牌第一版

```text
PhysicalMitigationRate = PhysicalDefense / (PhysicalDefense + 20)
```

`basic-attack`／`wolf-bite` 為物理（Physical）+ 可格擋（Blockable）；`shatter-strike` 為物理 + 不可格擋（NotBlockable）；`fireball`／`meteor-strike` 為魔法（Magic）+ 不可格擋。格擋與最終傷害全由伺服器決定。

裝備未來不再以 `ClassID AllowList` 作為方向；合法性收斂到持有權、欄位、手持衝突、裝備需求／標籤等無職業規則。

### 遭遇仇恨第一版（Encounter Threat V1）

以實際傷害驅動的仇恨已完成：穩定 `EntityID`、確定性同值判定、無效目標清除／替補、斷線／敗北／脫戰生命週期清理。脫戰也會清除暫時性的來源－目標戰鬥資源，失敗拉怪不得污染下一場遭遇。

### 地面掉落／背包正確性

- 公開地面掉落有伺服器權威且有界限的到期時間。
- 撿取／自動拾取／到期共用權威生命週期。
- 敗北角色不得撿取、裝備、卸下裝備。
- 掉落／背包／裝備修改維持世界擁有者（world-owner）路徑。

### 暫時狀態基礎

已有通用暫時狀態儲存與角色敗北／正式離開／怪物實體世代生命週期清理。現有 Fortify 只保留為舊制執行期／迴歸驗證證據，不再代表未來有 Oathguard 職業。

## 近期伺服器路線

### P0 — 無職業制基礎

1. 停止擴張任何職業限定遊戲內容。
2. 定義伺服器權威的角色屬性、已學技能、6 格戰鬥技能配置。
3. 定義通用與輔助固定能力的伺服器表示方式。
4. 將 20 技能逐步建立為通用動作／效果語義，不搬舊職業數值。
5. 將裝備合法性從職業政策遷移至無職業裝備需求。
6. 最後再處理 `ClassID`／職業資源／持久化／通訊協定遷移。

未定的技能數值先討論，不自行發明。

### P0 正確性閘門 — Tick／動作重入

目前沒有巢狀反擊／觸發／死亡動作產生器，因此不預建框架。未來一旦新增巢狀產生器，必須先定義執行順序並以「恰好一次」（exactly-once）測試保護。

### P1 — PvE／狀態／怪物能力

只在有正式技能或怪物契約後加入緩速（slow）、暈眩（stun）、中毒（poison）、增益（buff）、減益（debuff）、召喚（summon）等效果。狀態系統基礎已存在，不代表舊草稿數值自動升格。

### P1 — 物品實例

若加入耐久、強化、綁定、可交易狀態、實例隨機屬性，掉落／撿取／持久化／交易必須保存同一物品實例的權威事實。

### P2 之後

經濟交易、隊伍、任務，再後續才是寵物、郵件、私人商店、拍賣、製作、公會、戰爭、攻城、排行、釣魚、房屋。

## 產品呈現方向

- 暗色邊境奇幻，但遊戲資訊必須清楚。
- 2.5D／俯視距離下輪廓（silhouette）清楚。
- 玩家、NPC、怪物、掉落一眼可辨。
- 目標、攻擊開始、命中、擊敗、掉落生成清楚呈現。
- 繁中 UI 優先。
- 特效／音效由伺服器權威狀態／事件觸發。
