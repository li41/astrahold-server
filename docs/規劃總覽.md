## 固定 gameplay authority

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Server 是唯一 gameplay truth。Client 的 animation、VFX、UI、camera、prediction、root motion、raycast、smoothing 不得決定 gameplay outcome。

跨系統 identity 使用穩定 ID，例如 `EntityID`、`ArchetypeID`、`ItemArchetypeID`、`ItemInstanceID`、`ActionID`、`SkinID`。Server 不保存 Client asset path。

## 地圖／場景工作邊界：Client 主導

地圖與場景不是 Server-first roadmap。

- 地圖 layout、視覺動線、場景資產與 playable-space 迭代由正式 Three.js Client 主導。
- gpt-server 不預先規劃下一張地圖、新手村重做、城牆、入口、portal、siege gate、blocker 數量或 spawn layout。
- Client 做出需要 gameplay authority 的具體 slice 後，再透過 integration Issue／comment 回饋 Server。
- Server 只針對該需求定義必要的 authoritative facts，例如 collision／traversability、teleport、spawn、gameplay region、AI region、interaction legality 或 siege legality。
- Client scene node、asset path、raycast、visual collider 或 presentation layout 不會自動成為 Server gameplay truth。
- 已由 Client 正式規劃 handoff 的大陸 envelope、Region core 與地下地圖 authority metadata 可進 Server；這不代表 Server 反過來主導 Client 場景設計。

因此「做下一張地圖」、「重做 Emberwatch」、「新增攻城入口」不列入 Server 主動待辦，直到 Client 提供明確 handoff。

## 核心角色方向：無職業制

Astrahold 的正式方向是 **無職業配裝流派系統（Classless Build System）**：

```text
屬性配點
+ 裝備
+ 已學技能
+ 實戰技能配置
= 玩家配裝流派（Build）
```

固定原則：

- 固定職業不再決定裝備或技能合法性。
- 所有正式技能最終皆可學習。
- 裝備原則上皆可使用，只保留 item／slot／hand conflict／action requirement／base-stat requirement 等真正需要的限制。
- 不再新增新的職業限定 action、item 或 profession-only resource。
- durable character state 已 classless；歷史 `ClassID` 只留在必要 migration／compatibility boundary。
- `internal/actionresource` 擁有 generic resource definition；`internal/actionpolicy` 擁有 production action/resource policy。
- Client #21 已完成 classless runtime retirement並回傳 safe breaking boundary；Server Protocol v34 已正式移除 legacy message type 9／115／116／117，current `wrong_class` product semantics亦不存在。Type118 `CharacterTargetResourceState` 保持 ID=118 與原 authoritative semantics；歷史 `ClassID` 只留必要 persistence migration boundary。

### 無職業技能組 V1

正式技能池先固定 20 招：

```text
通用 4：瞬間移動術、日光術、防禦（Guard）、治癒術
近戰 4：重擊（Heavy Strike）、連斬（Flurry）、橫掃（Cleave）、處決（Execute）
遠攻 4：穿透射擊（Piercing Shot）、快速射擊（Rapid Shot）、箭雨（Volley）、牽制射擊（Pinning Shot）
法術 4：火焰彈（Fire Bolt）、冰霜爆發（Frost Burst）、隕星（Meteor）、奧術長矛（Arcane Lance）
輔助 4：體魄強健、通暢氣脈、靈力凝聚、加速術
```

實戰配置：

```text
basic-attack
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 從近戰／遠攻／法術 12 招中自由選 6 招
```

已定：體魄強健 = 力量 +5、通暢氣脈 = 敏捷 +5、靈力凝聚增加魔法攻擊（數值待定）、加速術 = ×1.3（作用項目／持續時間／冷卻待定）。其餘正式效果與技能取得方式不從舊職業數值自行推導。

## 可玩主線

優先把 MMORPG 基本 loop 做成值得玩的產品：

```text
移動
-> 選怪
-> 攻擊／被攻擊
-> HP / MP / cooldown
-> 死亡／重生
-> 擊殺
-> 掉落
-> 撿取
-> 背包
-> 使用物品
-> 裝備
-> 配裝流派／技能
-> 持久化
```

Client 地圖進度不再作為 Server gameplay 施工門檻；反過來，Server 也不替 Client 預先設計地圖。兩端只在正式 Protocol 與具體 authoritative integration point 對接。

## 已完成的 Server gameplay foundation

### 角色／技能／持久化

- 20 技能穩定目錄。
- authoritative learned-skill state。
- 6 格 combat loadout 與「必須為已學技能子集」的不變條件。
- character schema 現行 v13／save journal v12；六格、learned skills、六大 base stats、selected `SkinID` 都能 durable restore/save。
- 六大 base stats 正式中性值皆為 10；effective stats 由 base + learned passive truth 即時計算，不建立第二套 mutable stats store。

### Basic attack／六屬性

physical `basic-attack` 現行命中：

```text
HitChance = clamp(90% + (totalHit - totalEvasion) * 0.5 percentage points, 75%, 98%)
```

- attacker effective AGI、weapon accuracy、unique-equipment hit 組成 total hit。
- target effective AGI、unique-equipment evasion 組成 total evasion。
- Server 擲 hit/miss；miss 不傷害但仍 commit cooldown。
- production `one_hand_sword`、`one_hand_axe`、`mace` 的 basic-attack damage attribute 已明確為 Strength。
- eligible damage critical chance 已接 effective AGI：base 5%，AGI 超過 30 後每完整 +10 AGI 增加 1pp，再加 `CriticalRating * 0.5pp`，上限 30%。
- production 已有 `bow`／`crossbow`／`sling` item archetype，且其 basic-attack damage attribute 為 Agility；命中與傷害結果仍由 Server authoritative path 決定。

### 武器／盾牌／防具／unique equipment

- production catalog 目前共 **107 件 equipment archetype**：53 件武器、9 面盾牌、45 件防具；正式裝備欄為 MainHand／OffHand／Helmet／Chest／Gloves／Legs／Boots。
- 45 件防具 = 15 件低階散裝＋15 件中階三套裝＋15 件高階三套裝。
- 低階防具 0 詞綴；中階防具為 unique `ItemInstance` 且 Server 產生 1 條合法詞綴；高階防具為 unique `ItemInstance` 且產生 2 條不同合法詞綴。
- 高階星鑄壁壘／星影追獵／星輝法衣分別要求 durable base Constitution／Agility／Intelligence >= 18；live equip 與 durable restore 都由 Server 重新驗證，裝備加成不得滿足自身需求。
- 六套防具的 2/5 件效果由目前 equipped pieces 即時計算，不持久化第二份 set-active truth。
- WeaponType 是 basic-attack cadence owner；相同 WeaponType 共用同一基礎攻擊間隔，單件 `ItemArchetype` 不得覆寫。
- 18 類 V1 基礎節奏已 authored；空手 600ms。
- 盾牌 physical defense／block／magic reduction 與 incoming-damage owner path 已存在。
- fixed modifiers、unique affixes、armor set bonuses 共用 Server-owned equipment stat aggregation。
- unique equipment 已有 stable `ItemInstanceID`、Server-rolled affix、exact-instance equip/unequip、durable restore/save；現行 v34 繼承 Type119–121 的 authoritative semantics。
- Map1 怪物掉落的 exact `ItemArchetypeID`、金幣 `item_gold_coin`、quantity range 與第一輪 basis-point target 已定案於 [Map1-怪物掉落規劃](Map1-怪物掉落規劃.md)；尚未定案的是後續 Region 掉落、正式商店價格、任務、製作與完整經濟來源／分配。不得把來源待實作誤寫成 item archetype 尚未存在。

### 皮膚 WeaponType affinity

- gameplay identity 使用 Server-owned `SkinID`，不使用 Client asset path／Mixamo UUID／GLB path。
- 17 個有攻擊武器類型各有一個 affinity skin；空手不加成。
- selected skin 與 authoritative main-hand WeaponType 相符時，現行 formal scope 的 `basic-attack` raw physical damage flat +1。
- Client 透過現行 v34 繼承的 Type122 `AppearanceSnapshot` 讀 selected SkinID 與 Server 算好的 active bonus 0/1，不自行重算 gameplay。

### 遭遇／掉落／生命週期

- damage-driven encounter threat V1。
- despawn／defeat／leave／respawn／leash cleanup。
- 公開 ground drop 有 authoritative bounded TTL。
- pickup／autopickup／expiry／rollback 共用 authoritative lifecycle。
- defeated player 不得 pickup／equip／unequip。
- generic transient-status lifecycle foundation 已存在。

## 正確性閘門

- gameplay mutation 維持 authoritative Server owner path。

- 沒有實際執行對應 tests／CI，不得宣稱 PASS。
