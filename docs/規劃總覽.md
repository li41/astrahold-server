## 固定 gameplay authority

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

Server 是唯一 gameplay truth。Client animation、VFX、UI、camera、prediction、root motion、raycast、smoothing 不得決定 gameplay outcome。

## 核心角色設計：無職業

Astrahold 的正式未來方向已改為 **Classless Build System**：

```text
屬性配點
+ 裝備
+ 已學技能
+ 實戰技能配置
= 玩家 Build
```

- 固定職業不再決定裝備或技能合法性。
- 所有裝備原則上皆可使用，只保留物品／動作本身真正需要的非職業限制。
- 所有正式技能最終皆可學習。
- 舊職業名稱最多作為推薦 Build，不是 gameplay identity。
- 不再新增新的 class-gated action、class-only item 或 class-specific resource。
- 現有 v27 ClassID / class-gated runtime 仍是 legacy migration debt；在 Protocol / persistence 安全遷移前不直接拔除。

### Classless Skill Set V1

技能池固定先收斂為 20 招：

```text
通用 4：瞬間移動術、日光術、Guard、治癒術
近戰 4：Heavy Strike、Flurry、Cleave、Execute
遠攻 4：Piercing Shot、Rapid Shot、Volley、Pinning Shot
法術 4：Fire Bolt、Frost Burst、Meteor、Arcane Lance
輔助 4：體魄強健、通暢氣脈、靈力凝聚、加速術
```

實戰配置：

```text
basic-attack
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 從近戰／遠攻／法術 12 招中自由選 6 招
```

其中體魄強健 = 力量 +5、通暢氣脈 = 敏捷 +5、靈力凝聚增加魔法攻擊（數值待定）、加速術 = x1.3（作用項目／持續／CD 待定）。完整規格見 [無職業技能系統規劃](無職業技能系統規劃.md)。

## 現在的可玩主線

優先把 MMORPG 基本循環做成值得玩的產品：

```text
移動
-> 選怪
-> 攻擊 / 被攻擊
-> HP / MP / cooldown
-> 死亡 / 重生
-> 擊殺
-> 掉落
-> 撿取
-> 背包
-> 使用物品
-> 裝備
-> Build / 技能
-> 持久化
```

Client 新手村進度不再作為 Server gameplay 施工門檻；只在 Protocol consumption / runtime integration 真正需要時留下整合 Issue。

## 已完成的 Server gameplay foundation

### 低階武器／裝備 v1

目前有 5 把低階主手、3 面盾牌、MainHand / OffHand、武器體型傷害、攻速、Server-owned accuracy、盾牌物防／格擋／魔法減傷與裝備持久化。

低階裝備目前**尚無正式取得方式**；沒有怪物掉落、掉率、商店、材料兌換、任務、製作、初始裝備或價格。不得自行補經濟內容。

### 武器命中 v1

低階武器 entity-target `basic-attack`：

```text
HitChance = clamp(90 + accuracy_modifier * 2, 75, 98)
```

Server 擲 0..99 命中 roll；miss 不扣 HP、產生 authoritative miss outcome，且攻擊 cooldown 仍成立。

### 盾牌 v1

```text
PhysicalMitigationRate = PhysicalDefense / (PhysicalDefense + 20)
```

`basic-attack` / `wolf-bite` 為 Physical + Blockable；`shatter-strike` 為 Physical + NotBlockable；`fireball` / `meteor-strike` 為 Magic + NotBlockable。格擋與 final damage 全由 Server 決定。

裝備未來不再以 ClassID AllowList 作為方向；合法性收斂到 ownership、slot、hand conflict、equipment requirement / tag 等 classless 規則。

### Encounter threat v1

actual-damage-driven threat 已完成：stable EntityID、deterministic tie-break、invalid target prune / fallback、disconnect / defeat / evade lifecycle clear。Evade 亦清 transient source-target combat resource，failed pull 不得污染下一場 encounter。

### Ground drop / inventory correctness

- Public ground drop 有 Server-owned bounded expiry。
- pickup / auto-loot / expiry 使用 authoritative lifecycle。
- defeated actor 不得 pickup、equip、unequip。
- loot / inventory / equipment mutation 保持 world-owner path。

### Transient status foundation

已有 generic transient status store 與 defeat / leave / monster-incarnation lifecycle clear。現有 Fortify 只保留為 legacy runtime / regression evidence，不再代表未來有 Oathguard 職業。

## 近期 Server roadmap

### P0 — Classless foundation

1. 停止擴張任何 class-gated gameplay。
2. 定義 authoritative attributes / learned skills / 6-slot combat loadout。
3. 定義通用與輔助固定能力的 Server representation。
4. 將 20 技能逐步建立成 generic action/effect semantics，不搬舊職業數值。
5. 將 equipment legality 從 class policy 遷移至 classless requirements。
6. 最後再處理 ClassID / class resource / persistence / Protocol migration。

未定的技能數值先討論，不自行發明。

### P0 correctness gate — Tick / action reentrancy

目前沒有 nested counter / proc / death action producer，因此不預建 framework。未來一旦新增 nested producer，必須先定義 ordering 並以 exactly-once tests 保護。

### P1 — PvE / status / monster abilities

只在有正式技能或怪物 contract 後加入 slow、stun、poison、buff、debuff、summon 等效果。Status foundation 已存在，不代表舊草稿數值自動升格。

### P1 — Item instance

若加入 durability、enchant、binding、tradable state、instance roll，drop / pickup / persistence / trade 必須保存同一 item instance truth。

### P2+

Economy transaction、Party、Quest，再後續才是 pet、mail、private shop、auction、crafting、guild、war、siege、ranking、fishing、housing。

## 產品呈現方向

- 暗色邊境奇幻，但 gameplay 必須清楚。
- 2.5D / 俯視距離下 silhouette 清楚。
- 玩家、NPC、怪物、掉落一眼可辨。
- target、attack started、hit、defeated、loot spawned 清楚呈現。
- 繁中 UI 優先。
- VFX / audio 由 Server authoritative state / event 觸發。
