# 星壘 Astrahold — 待辦與待討論

本文件整理目前 **gpt-server 可直接施工的待辦、等待 Client 的整合、需要產品決策的議題，以及明確暫不由 Server 規劃的範圍**。

本文件不是第二份 gameplay contract。若內容與正式 Server source／Protocol contract 衝突，以正式 source／contract 為準；exact SHA、CI、active Issue 與 blocker 以 [專案狀態](專案狀態.md) 為準；長期方向以 [規劃總覽](規劃總覽.md) 為準。

## 工作分類原則

- **可直接做**：不需要新增產品語義，且能以現有 Server authority／contract 判定正確性。
- **等待 Client**：Server contract 已存在，剩餘工作由正式 Client 消費、呈現或回報 integration requirement。
- **待討論**：會新增 gameplay、成長、經濟、取得方式、數值或新 Protocol semantics；沒有明確決策前 Server 不猜。
- **暫不規劃**：目前不是 Server-first 工作；不以 infrastructure-first／framework-first／content-churn 填空。

## P0 — Server correctness／contract 收斂

Protocol v29 七欄裝備與完整 45 件防具已落地。Server 目前沒有已確認需要另開新 Protocol 的 armor blocker。

防具 correctness 要求：

- 正式七欄：`main_hand`、`off_hand`、`helmet`、`chest`、`gloves`、`legs`、`boots`。
- 45 件防具：15 低階、15 中階、15 高階。
- 中階 unique armor：1 條 Server-rolled affix。
- 高階 unique armor：2 條不同 Server-rolled affix。
- 星鑄壁壘／星影追獵／星輝法衣的 requirement 分別只看 durable base Constitution／Agility／Intelligence >= 18。
- live equip 與 durable restore 都必須重新驗 requirement；裝備、詞綴、set bonus、passive/status bonus 不得滿足自身 requirement。
- 2/5 件套裝效果由當下 authoritative equipped pieces 重算，不保存第二份 set-active state。

本輪 exact-head validation 與 Client handoff 狀態見 [專案狀態](專案狀態.md)。

## 待產品／使用者決策

### 1. 裝備取得／經濟來源

目前 production catalog 已有 **107 個 equipment archetype**：

- 53 武器
- 9 盾牌
- 45 防具

因此「中高階 item 還不存在」不再是待辦。仍未定的是玩家如何取得：

- 怪物掉落表與掉率
- 商店與價格
- 初始裝備
- 任務獎勵
- 製作／材料兌換
- 交易／經濟價值

沒有正式決策前 Server 不自行補完。

### 2. 角色成長與屬性點 mutation

已定方向：六大基礎屬性、中性基準 10、創角額外 10 點、創角單項最多 +5、51 級後每級 +1 點。

仍需決定正式 character level/progression owner、創角配點 intent、51 級後點數 mutation，以及是否有重置與其成本／限制。

### 3. 技能取得／學習與六格編輯

已有 20 技能 stable ID、learned-skill authoritative state、6 格 combat loadout 與 durable persistence。

仍需決定技能取得／學習、忘卻／重置、六格何時可編輯與 Client intent/rejection semantics。

### 4. 尚未定案的技能效果／數值

至少包含日光術、防禦、治癒術、瞬間移動術，以及 12 個近戰／遠攻／法術技能的正式傷害、距離、冷卻、資源與係數；靈力凝聚與加速術仍有部分數值／作用範圍未定。

### 5. Skin selection mutation

目前已有 durable selected `SkinID` 與 Type122 Server->Client snapshot，但玩家何時／在哪裡切換 skin 的正式產品入口與 legality 尚未定義。

## 地圖／場景 — Client 主導

Client 已 handoff 的正式 World Master authority facts 可由 Server 保存並用於 movement／region／map authority；Server 仍不主動設計下一張 Client 地圖、場景資產、視覺動線或 presentation geometry。

新的 collision／portal／spawn／AI region／siege legality 只有在 Client 提供明確 playable slice 或使用者直接定義需求後才施工。
