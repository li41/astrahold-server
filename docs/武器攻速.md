# 武器攻速、普攻距離、持握、階級與負重規則

本文件記錄 Astrahold 正式 Server 的武器基本攻擊、持握需求、階級進程與裝備負重規則。Server 是唯一 gameplay authority；Client 只依 authoritative state/events 呈現動畫，不得以動畫、本地計時、raycast、asset mapping 或本地裝備資料決定攻擊是否合法、距離、傷害、攻速、持握或負重結果。

## 權威規則

- 持械普攻的基礎間隔由 `WeaponType -> BasicAttackIntervalMS` 持有。
- 同一 `WeaponType` 的所有 `ItemArchetypeID` 共用同一基礎攻速；單件武器不得覆寫。
- 遠程普攻距離由 `WeaponType -> BasicAttackRange` 持有；單件武器與階級不得自行延長距離。
- 持握需求由 `WeaponType` 共用規則持有；同一武器型別的低階、中階、高階不得各自改成不同手數。
- 沒有正式距離覆寫的武器沿用 `basic-attack` action definition 的 `4.5` 公尺。V1 只有投石索、弓、十字弓覆寫普攻距離。
- 空手沒有裝備 `WeaponType`，使用 `basic-attack` action definition 的 `600 ms` 基礎間隔與 `4.5` 公尺距離。
- Server 在 action prepare/commit path 決定實際 cooldown 與 range legality；Client 不得以本地 raycast 決定命中是否合法。
- 盾牌不產生 basic attack；釣竿是道具，不列入武器攻速。
- 未來若有裝備、Buff 或屬性攻速加成，仍由 Server 算出 effective cadence；不得要求 Client 自行套倍率決定 gameplay timing。

### 力量與敏捷邊界

- 所有近戰武器的物理基本攻擊傷害統一吃力量，包括匕首、指虎、鉤爪與雙刀。
- 弓、十字弓、投石索的物理基本攻擊傷害吃敏捷。
- 敏捷仍負責既有的物理命中、閃避、遠程物理傷害與高敏捷暴擊成長；不再同時提供近戰武器傷害。
- 法杖 V1 不因 `WeaponType` 自動取得力量、敏捷或智力的物理基本攻擊傷害加成。
- 裝備詞綴提供的力量、敏捷、體質、智力、精神、魅力現在都會進入 Server 的有效主屬性計算；不會只存在於 `ItemInstance` 而不影響戰鬥公式。

## 正式 V1 武器階級進程

- 17 種正式 `WeaponType` 均已有低階、中階、高階 Server 原型。
- 低階有 17 條代表武器線，另保留 2 把單手劍替代款；中階 17 把、高階 17 把，合計 **53 把正式武器**。
- 中階武器必須是唯一 `ItemInstanceID`，建立時 Server 產生恰好 1 條合法隨機詞綴。
- 高階武器必須是唯一 `ItemInstanceID`，建立時 Server 產生恰好 2 條不同 `AffixID` 的合法隨機詞綴。
- 低階 archetype-only 裝備與中／高階唯一實例共用同一 `WeaponType` 攻速、射程、持握與物理普攻主屬性規則。
- `Inventory.MainHand()` 對 archetype 裝備與唯一實例都提供權威 `ItemArchetypeID`；普攻傷害、命中、攻速、射程與 skin affinity 都透過這個 archetype 再解析 `WeaponType`，不由 Client 或 `ItemInstanceID` 字串推論。
- 中／高階目前沿用同一武器線低階代表的重量與材質；V1 不建立「階級越高重量必然改變」的額外規則。
- 釘棒的固定 `ExtraDamage` 為低階 +1、中階 +2、高階 +3。
- 第一版不因武器階級加入破甲、流血、額外觸發、多段攻擊、元素觸發等複雜效果。

### 固定屬性與隨機詞綴

固定 archetype 屬性與隨機實例詞綴是不同生命週期，但最後進入同一 Server 權威裝備屬性聚合結果：

```text
ItemArchetype fixed modifiers
+ ItemInstance rolled affixes
-> equipmentstats.Modifiers
-> authoritative combat / effective primary stats
```

- `static_modifiers` 是 `ItemArchetypeID` 固定資料，不會因掉落、交易、重登而重骰。
- 隨機詞綴屬於 `ItemInstanceID`，依既有中階 1 條／高階 2 條規則生成並持久化。
- 目前正式武器中只有法杖 authored 固定魔法威力：低階 +1、中階 +2、高階 +4。
- 法杖固定魔法威力可以與同一唯一實例骰出的魔法威力詞綴疊加；兩者都由 Server 套入直接魔法傷害。
- 固定屬性資料結構是通用裝備能力，不建立法杖專用戰鬥特例；未來防具／套裝若正式定案可沿用同一聚合路徑。

## 正式 V1 持握規則

- 單手、可與盾牌並存：`one_hand_sword`、`dagger`、`one_hand_axe`、`one_hand_spear`、`warhammer`、`morning_star`、`mace`、`sling`。
- 雙手、佔用兩個 gameplay 手部欄位：`two_hand_sword`、`two_hand_axe`、`two_hand_spear`、`knuckles`、`claw`、`dual_blades`、`bow`、`crossbow`、`staff`。
- `knuckles`、`claw`、`dual_blades` 的「雙手」只代表 Server gameplay 欄位佔用，不規定 Client 必須如何掛模型、播動畫或表現左右手。
- 舊有 `item_training_blade` 維持單手相容行為。
- 身上已有盾牌時，Server 拒絕裝上雙手武器；已裝雙手武器時，Server 拒絕裝盾。
- 衝突裝備不會自動卸下另一欄；玩家必須先主動卸下衝突裝備，避免一次意圖暗中產生第二個 gameplay mutation。
- 低階 `ItemArchetypeID` 裝備與中／高階 `ItemInstanceID` 裝備使用同一持握合法性。
- 持久化存檔拒絕雙手武器＋盾牌非法狀態；讀檔同樣拒絕歷史或異常快照把非法組合重新帶回世界。
- Client 不得自行推論或放寬持握合法性；Server 裝備狀態才是 gameplay truth。

## 正式 V1 負重規則

- 每個角色的最大攜帶重量固定為 **100**。
- 物品重量由 Server 的 `ItemArchetypeID` 資料持有，必須是正整數。
- 背包內物品與已裝備物品都計入同一個總負重；裝備／卸下不會改變總負重。
- 拾取、加入背包或交換後若會超過 100，Server 原子拒絕該操作；不會先吞掉地上掉落再回滾。
- 移除、丟棄或消耗物品後會立即釋放對應負重。
- 隨機詞綴與 `ItemInstanceID` 不改變基礎重量。
- V1 不由力量、職業、等級或裝備效果提高負重上限。
- V1 沒有輕載／重載／超重分段，也沒有超重後降低移速的狀態；到達上限後直接拒絕新增重量。
- 重量不影響移動速度、攻擊間隔、施法速度、傷害、命中、閃避、冷卻、屬性或動畫速度。

## 不做裝備耐久度

- Astrahold V1 不建立裝備耐久值、磨損、破損或修理系統。
- 攻擊、受擊、死亡、裝備與卸下都不降低任何耐久值。
- 不建立修理費、修理 NPC、耐久協定欄位或預留的耐久 gameplay state。
- 程式中的 `durable...` 命名若出現，是指「可持久化保存的狀態」，不是物品磨損耐久度。

## 實作位置

- `internal/equipmentcatalog/default.json`：53 把武器、3 面現有盾牌、`WeaponType` 共用規則與固定屬性資料。
- `internal/equipmentcatalog/static_modifiers.go`：固定 archetype 屬性的穩定 ID、驗證與 canonicalization。
- `internal/equipmentcatalog/hand_requirement.go`：正式 `WeaponType` 單手／雙手 gameplay 佔用規則。
- `internal/equipmentstats/stats.go`：固定屬性與隨機詞綴的權威聚合／合併。
- `config/combat-actions.json`：空手與沒有距離覆寫的 `basic-attack` 基礎規則，目前正式值為 `600 ms`、`4.5 m`。
- `internal/worldruntime/equipment_affix_stats.go`：目前已裝備 archetype 固定屬性＋唯一實例隨機詞綴合併入口。
- `internal/worldruntime/character_stats.go`：裝備六大主屬性與已學被動共同推導有效主屬性。
- `internal/worldruntime/weapon_basic_attack.go`：持械普攻傷害、命中、攻速與武器 archetype 解析。
- `internal/worldruntime/weapon_basic_attack_range.go`：持械普攻距離覆寫，發生在 Server 距離合法性判定前。
- `internal/worldruntime/equipment_hands.go`：兩條裝備入口與持久化共用的持握合法性。
- `internal/worldruntime/inventory.go`：角色最大攜帶重量 `100`、正式物品重量來源，以及存檔／讀檔持握檢查。
- `internal/inventory/inventory.go`：負重上限與裝備狀態；`MainHand()`／`OffHand()` 對 archetype 與唯一實例提供一致 archetype 查詢。
- `internal/equipmentcatalog/weapon_progression_test.go`、`internal/iteminstance/default_weapon_progression_test.go`、`internal/worldruntime/static_modifier_integration_test.go`、`internal/worldruntime/unique_weapon_archetype_test.go`：三階武器、固定屬性、唯一實例普攻規則測試保護。

## 呈現邊界

Client 的動畫實測可作為商用品質與 presentation constraint 的輸入，但不能反向成為 gameplay authority。若動畫片段短於 Server 間隔，可播完後回待機等待；若動畫需要裁切或調整播放速率，Client 可以處理呈現，但不得延後 Server 已合法的下一次攻擊。遠程武器的準星、射線、拋射物與特效只負責呈現，不能自行放寬或縮短 Server 的合法攻擊距離。雙手持握的 gameplay 佔用也不要求 Client 以特定模型掛點或動畫方式呈現。
