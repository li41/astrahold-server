# 星壘 — 裝備材質規劃

本文件定義現行正式 Server equipment catalog 的主材質規劃，以及第一版材質 gameplay 規則。

Server 是唯一 gameplay authority。材質是 `ItemArchetypeID` 的穩定 gameplay metadata；Client 的貼圖、PBR、shader、mesh material 名稱與 asset path 不得決定 gameplay outcome。

本文件目前是**規劃契約**，不是已完成實作。現行 source 的 `Definition.Material string` 仍存在歷史自由字串與複合字串；後續實作應收斂成穩定 `MaterialID`／等價 typed identity，再由 tests 保護。未實際修改 source 與通過 CI 前不得宣稱材質 gameplay 已上線。

## 一、主材質原則

每個裝備 archetype 只指定一個 gameplay **主材質**。

主材質代表主要承擔該裝備玩法身分的材料：

- 劍、匕首、斧、矛、鎚、拳套、爪、雙刀：看主要攻擊部件，不因木柄、皮纏或鏈條再建立第二份 gameplay 材質 truth。
- 弓：看弓身。
- 弩：看主要弓臂／機構的正式材質。
- 法杖：看杖身。
- 盾牌：看主要承力／防護結構。
- 防具：看主要防護層。

次要構造材料未來可存在 crafting recipe，但不參與 V1 材質 gameplay 判斷。

`ItemInstance` 不重新骰材質；unique instance 一律繼承其 `ItemArchetypeID` 的主材質。

## 六、銀對不死 V1

### 正式效果

只在下列條件全部成立時啟用：

1. 攻擊來源是玩家目前權威裝備的 `main_hand`。
2. `main_hand` 的 `ItemArchetypeID` 主材質為 `silver`。
3. 本次傷害是正式 `basic-attack` 的武器物理傷害。
4. 目標具有 Server-owned 穩定不死系分類 `undead`。

效果：

```text
銀對不死加成後原始物理傷害 = floor(原始物理傷害 × 1.20)
```

計算順序固定為：

```text
武器／角色／裝備對本次 basic-attack 的 raw physical damage 聚合
-> 若 silver + undead，×1.20 並向下取整
-> critical
-> 目標物理防禦／其他 mitigation
-> block
-> 最終 authoritative damage
```

### 不作用項目

V1 不作用於：

- spell damage
- DoT
- poison／bleed／burn 等 status tick
- thorns／reflect
- summon damage
- shield damage
- armor
- off-hand 銀材質
- Client 自行判定的怪物名稱、mesh、材質或 UI tag

銀加成不因身上多件銀裝疊加；判斷只看實際造成該次武器普攻的主手武器。

### 不死系分類

`undead` 必須是 Server-owned gameplay identity／tag，由 monster archetype 或等價正式 gameplay definition 決定。

不得使用：

- 顯示名稱包含「骷髏／殭屍」
- Client asset path
- mesh 名稱
- animation 名稱
- VFX

來推導是否為不死系。

目前尚未指定哪些正式怪物屬於 `undead`；等怪物內容表定案時逐 archetype 指定，不自行從舊名稱猜測。

## 七、目前只有銀有材質效果

V1 明確不替其他材質增加隱性能力：

- 鐵沒有額外攻防倍率。
- 鋼沒有額外攻防倍率。
- 星鋼沒有額外攻防倍率。
- 木／強化木／秘紋木／星木沒有額外元素效果。
- 皮革／強化皮革／星影皮革沒有額外閃避或移速。
- 布／秘紋布／星輝織物沒有額外魔法倍率。

裝備實際強度仍由 archetype 本身的傷害、防禦、重量、static modifier、requirement、affix 與 set bonus 決定。

材質先作為：

- 穩定裝備分類
- 未來 crafting recipe hook
- 未來 repair／salvage／economy hook
- 少量明確 gameplay interaction 的依據

但不建立全域「材質倍率表」。

## 八、Server 實作方向

後續實作 slice 應遵守：

1. 將目前自由 `Material string` 收斂為穩定 `MaterialID` 或同等 typed identity；不保留依字串包含關鍵字判斷 gameplay 的做法。
2. catalog validation 必須拒絕未知材質。
3. 107 件 production equipment 全部有且只有一個正式主材質。
4. unique `ItemInstance` 繼承 archetype 材質，不重骰、不持久化第二份材質 truth。
5. 增加 Server-owned `undead` gameplay tag／category owner；若現行怪物 archetype 尚無通用 tag，應做通用分類，不為單一骷髏怪硬編特殊判斷。
6. 銀 V1 加成進現有 authoritative basic-attack damage owner path；Client 不參與 multiplier 計算。
7. regression 至少覆蓋：silver+undead、silver+non-undead、non-silver+undead、銀盾無加成、spell/status 不加成、critical/mitigation/block 順序。
8. 此變更若不新增 wire field，不需要為材質 gameplay 單獨升 Protocol；Client 若要顯示材質與不死加成 tooltip，再另外 handoff presentation requirement。

## 九、未定案

本文件不自動決定：

- repair cost
- durability
- crafting recipe
- salvage quantity
- 商店價格
- 掉落來源
- 材質稀有度
- 銀以外材質特殊效果
- 星鋼／星木／星影皮革／星輝織物的額外 gameplay ability
- 銀對玩家／野獸／惡魔／元素等非不死分類效果
- weapon skill 是否在未來繼承銀 bonus

這些必須另行定案。
