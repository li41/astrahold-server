# 第一大陸與地下地圖 Server 權威範圍

本文件記錄從正式 Client `ai-working-gpt-client` World Master Layout v1.0 同步到 Server 的地理 authority 邊界。正式可執行資料以 `worlds/castle-sandbox/gameplay.json` 為準；本文件只說明語義與來源邊界。

## Authority 分層

Server 仍是 gameplay 唯一 authority：

```text
Client Intent
-> Go Server Validate / Decide
-> Authoritative State / Events
-> Client Presentation
```

地圖資料在 Server 分成三種不同語義：

1. `Surface.Bounds`：authoritative movement envelope。玩家 movement 仍由 `internal/navigation` 檢查 surface、blocker、portal 等資料決定是否合法。
2. `RegionCore.Polygon`：authoritative geography / region membership。polygon 可重疊，不會自動成為 collision wall 或 movement blocker。
3. `MapAuthority`：stable MapID、入口 anchor，以及 Client World Master 已正式定稿的地下地圖核心尺度。未 production 的地下 map 不會因為登記 MapAuthority 就自動產生 navigation surface、portal 或 collision。

Client 的 terrain tile、256m chunk grid、render padding、transition belt、mesh 高度與 asset path 不屬於 Server gameplay truth，沒有同步進 Server。

## 第一大陸 movement envelope

目前連續第一大陸 authoritative ground envelope：

- `minX = -2600`
- `maxX = 2600`
- `minZ = -900`
- `maxZ = 4100`
- 尺度：`5200m × 5000m`

`worlds/castle-sandbox/gameplay.json` 的既有 world ID 暫時保留，以避免在沒有正式 identity migration 的情況下建立第二個 world identity；它不再代表舊的百米級 sandbox 尺度。

## 現行納入範圍

目前 Client `ai-working-gpt-client` 的正式 `WORLD_MASTER_PLAN.md` 中，已定義的第一大陸核心地理與地下地圖資料均已納入 Server representation：

- 第一大陸完整 movement envelope；
- 12 個地表 Region core polygon；
- 9 個地下地圖 stable MapID；
- 9 個地下入口 world-space anchor；
- 3 個已定稿 exact 地下 envelope／層數／深度／主路線；
- 6 個尚未有精確 envelope 的正式規模分級。

先前文件曾提及約 `(600,5200)` 的 far-north island；最新正式 Client World Master 已沒有這項定義，因此該敘述已移除，不再視為 current map truth。若 Client 之後重新正式加入獨立島嶼或其他新 map，需以新的 stable MapID / RegionID handoff 再同步，不沿用過時座標。

Emberwatch 最新 Client presentation / terrain production coverage 為 `X=-600..1000 / Z=-900..505`，一路延伸到正式南岸水際。這個 production envelope **不是** Server 的 `RegionCore.Polygon`，也不是第二張地圖或新的 movement boundary。

目前 Server 決策：

- 第一大陸 `Surface.Bounds` 本來就涵蓋 `Z=-900`，因此南岸延伸不需要新 world identity、portal 或 movement surface。
- `region_emberwatch` 仍代表既有 authoritative geography core；Client 擴大 production coverage 不會自動擴張 gameplay region membership。
- 在 Client 沒有 handoff 新的 gameplay geography polygon 前，`worlds/castle-sandbox/gameplay.json` 的 `region_emberwatch` polygon 維持不變；`internal/gameplayworld/region_test.go` 的 exact-data guard 亦維持現行控制點。
- 南岸 presentation 可以先在同一 continuous overworld 製作；若未來南岸需要 AI region、spawn、collision、interaction 或其他 gameplay membership，再由具體 Client handoff 建立相應 Server authority。
