# 星壘 — 角色屬性與成長規劃

本文件定義 Astrahold 無職業角色的六大基礎屬性、創角配點與升級配點第一版。這些規則屬於伺服器權威遊戲資料；Client 只能提交配點意圖與呈現 Server 回傳結果，不得自行修改角色屬性、可用點數或衍生戰鬥值。

## 一、六大基礎屬性

正式六屬性：

- 力量：近戰物理傷害；未來也影響負重。
- 敏捷：物理命中、閃避、屬性來源爆擊、遠程物理傷害。
- 體質：最大生命與生命回復。
- 智力：魔法威力。
- 精神：最大魔力與魔力回復。
- 魅力：可帶領的召喚物、寵物與城主士衛總數。

角色持久化必須保存可重建配點結果的權威資料。裝備、被動技能與暫時效果若改變六屬性，所有衍生值仍由 Server 重新計算；Client 不保存或決定最終 gameplay truth。

概念分層：

```text
基礎屬性 = 10 + 創角配點 + 升級配點
有效屬性 = 基礎屬性 + Server 認可的裝備／被動／暫時修正
```

現行技能組已有力量、敏捷類被動，因此有效屬性必須能承接這類 Server-owned modifier。V1 沒有提供魅力或「可帶領數量」的技能；不得另建技能專用的統御容量加成。

## 二、力量

10 點力量為中性基準。第一版近戰物理傷害加成：

```text
近戰物理傷害加成 = floor(max(力量 - 10, 0) / 2)
```

對照：

| 力量 | 近戰物理傷害加成 |
|---:|---:|
| 10–11 | +0 |
| 12–13 | +1 |
| 14–15 | +2 |
| 16–17 | +3 |
| 18–19 | +4 |
| 20–21 | +5 |

力量低於 10 時，V1 不額外施加近戰傷害懲罰。負重確定由力量影響，但重量單位與換算公式等背包／重量制度正式定案後再補，不自行發明。

## 三、敏捷

### 物理命中值

```text
物理命中值修正 = 敏捷 - 10
```

因此 10 = 0、11 = +1、12 = +2；若有效敏捷因負面效果低於 10，9 = -1、8 = -2。

物理命中值是評分值，不直接等於百分比。正式彙總與命中率公式：

```text
總物理命中值
= 敏捷來源物理命中值
+ 武器命中修正
+ 裝備物理命中詞綴
+ Server 認可的其他修正

總閃避值
= 敏捷來源閃避值
+ 裝備閃避詞綴
+ Server 認可的其他修正

物理命中率
= clamp(90% + (攻擊者總物理命中值 - 目標總閃避值) × 0.5 個百分點, 75%, 98%)
```

每 1 點「物理命中值相對於目標閃避值的淨優勢」等於 0.5 個百分點命中率。命中擲骰與最終結果只能由 Server 決定；Client 不得自行換算或擲骰。

### 遠程物理傷害

```text
遠程物理傷害加成 = floor(max(敏捷 - 9, 0) / 3)
```

| 敏捷 | 遠程物理傷害加成 |
|---:|---:|
| 10–11 | +0 |
| 12–14 | +1 |
| 15–17 | +2 |
| 18–20 | +3 |
| 21–23 | +4 |

### 閃避值

```text
閃避值修正 = floor(max(敏捷 - 10, 0) / 2)
```

| 敏捷 | 閃避值修正 |
|---:|---:|
| 10–11 | +0 |
| 12–13 | +1 |
| 14–15 | +2 |
| 16–17 | +3 |

閃避值只參與物理命中對抗；V1 魔法採必中，不用閃避值對抗魔法。每 1 點閃避值相對使攻擊者的物理命中率降低 0.5 個百分點，並受上述 75%～98% 最終命中率界限約束。

### 屬性來源爆擊

敏捷 40 前不提供額外爆擊；之後每 10 點提高 1 個百分點：

```text
屬性爆擊加成（百分點） = floor(max(敏捷 - 30, 0) / 10)
```

| 敏捷 | 屬性爆擊加成 |
|---:|---:|
| 0–39 | +0% |
| 40–49 | +1% |
| 50–59 | +2% |
| 60–69 | +3% |
| 70–79 | +4% |

對於正式允許爆擊的動作，第一版爆擊率公式：

```text
最終爆擊率
= min(30%, 5% + 屬性爆擊加成 + 爆擊值 × 0.5 個百分點)
```

- 基礎爆擊率為 5%。
- 每 1 點爆擊值提供 0.5 個百分點爆擊率。
- 最終爆擊率硬上限為 30%。
- 智力、力量不再另外提供一套屬性爆擊階梯。
- 哪些動作允許爆擊、爆擊傷害倍率仍需在正式戰鬥／技能規格中定案；不得因存在爆擊率就自動令所有傷害事件可爆擊。

## 四、智力

### 魔法威力

```text
魔法威力加成 = floor(max(智力 - 10, 0) / 5)
```

| 智力 | 魔法威力加成 |
|---:|---:|
| 0–14 | +0 |
| 15–19 | +1 |
| 20–24 | +2 |
| 25–29 | +3 |
| 30–34 | +4 |

V1 魔法採**必中**：魔法動作通過 Server 的目標、距離、視線、資源、冷卻、免疫／合法性等檢查後，不再額外進行隨機命中／未命中擲骰。必中不代表繞過合法性、魔法防禦、減傷、免疫或其他正式效果。

因此 V1 不存在「魔法命中值」衍生屬性，也不保留魔法命中裝備詞綴。智力不直接增加爆擊；最終法術傷害仍由 Server 的正式技能／戰鬥公式結算。

## 五、基礎生命與魔力

Astrahold 的玩家基礎 HP／MP 數值尺度參考 `li41/myriad-throne-server`，但不搬舊職業模板、隨機升級或職業倍率。

舊專案創角資料：

- 舊四職 `base_hp` 為 12／14／15／16，套入各職預設 CON 後，Lv.1 MaxHP 約落在 13–18。
- 舊四職 `base_mp` 為 2／4／6／10，套入各職預設 WIS 後，Lv.1 MaxMP 約落在 2–11。
- 舊每級 HP 基礎成長為 7／10／11／17，再加 `0..1` 隨機與高 CON bonus。
- 舊 MP 每級成長由 WIS 階梯與職業倍率共同決定。

Astrahold 為無職業系統，因此 V1 將舊專案的中間尺度收斂為固定、可重建的 Server-authoritative 基線：

```text
BaseMaxHP(Level) = 15 + 11 × (Level - 1)
BaseMaxMP(Level) = 6 + 2 × (Level - 1)
```

其中 `Level >= 1`。不使用每級隨機骰，不依職業套不同 growth multiplier。

基礎值對照：

| 等級 | BaseMaxHP | BaseMaxMP |
| ---: | ---: | ---: |
| 1 | 15 | 6 |
| 5 | 59 | 14 |
| 10 | 114 | 24 |
| 15 | 169 | 34 |
| 18 | 202 | 40 |
| 22 | 246 | 48 |
| 50 | 554 | 104 |

最終最大生命／魔力：

```text
MaxHP
= BaseMaxHP(Level)
+ 體質來源額外最大生命
+ 裝備／套裝／詞綴／被動／暫時效果的 MaxHP 修正

MaxMP
= BaseMaxMP(Level)
+ 精神來源額外最大魔力
+ 裝備／套裝／詞綴／被動／暫時效果的 MaxMP 修正
```

規則：

- `BaseMaxHP`／`BaseMaxMP` 是角色等級帶來的本體基線，不是可由 Client 傳入的值。
- 體質／精神提供的是另外一層 derived bonus，不永久烙進 base HP／MP。
- 升級時不做 HP／MP random roll；相同 Level、相同有效屬性與相同裝備狀態必須得到相同 MaxHP／MaxMP。
- 現行 runtime 的 `CharacterMaxHP=1000`／`DefaultMaxMP=100` 只視為舊 playtest baseline；正式 progression slice 必須改由上述公式推導，不能把 1000／100 升格成正式角色基礎值。
- HP／MP 回復規則另行規劃，不因基礎量表定案而自動推導。

## 六、體質

體質 15 以下不提供額外的「屬性來源最大生命」；16 起，每超過 15 一點，依角色等級成長：

```text
體質額外最大生命 = 角色等級 × max(體質 - 15, 0)
```

例：

| 等級 | 體質 | 額外最大生命 |
|---:|---:|---:|
| 20 | 15 | 0 |
| 20 | 16 | 20 |
| 20 | 18 | 60 |
| 50 | 18 | 150 |
| 50 | 20 | 250 |

這是屬性提供的額外生命，不取代角色本體／等級的基礎生命模型。必須由目前有效體質重新推導，不能在升級時把裝備提供的體質永久烙進角色存檔。

體質同時影響生命自然回復，但回復 tick、上限與最終公式尚未正式定案。

## 七、精神

精神使用階梯制：

| 精神 | 魔力成長階級 |
|---:|---:|
| 0–9 | 0 |
| 10–14 | +1 |
| 15–20 | +2 |
| 21–24 | +3 |
| 25–28 | +4 |
| 29–32 | +5 |
| 33 以上 | +6 |

```text
精神額外最大魔力 = 角色等級 × 精神對應魔力成長階級
```

這同樣是屬性來源的額外魔力，不取代角色本體／等級基礎魔力；裝備切換後必須由目前有效精神重新推導，不能永久烙進角色存檔。

精神同時影響魔力自然回復；魔法防禦、異常抗性、回復 tick 與最終公式待相關戰鬥系統定案，不在本版自行延伸。

## 八、魅力與可帶領數量

這套系統刻意保持單純，不建立多層「統御容量」。正式名稱使用**可帶領數量**。

召喚物、寵物、城主士衛共用同一個總數上限：

| 魅力 | 可帶領數量 |
|---:|---:|
| 0–14 | 1 |
| 15–19 | 2 |
| 20–24 | 3 |
| 25–29 | 4 |
| 30 以上 | 5 |

等價公式：

```text
可帶領數量 = min(5, 1 + floor(max(魅力 - 10, 0) / 5))
```

固定規則：

- 每一隻受控召喚物、寵物或城主士衛都只算 1，不依大小、強弱、稀有度另外加權。
- 三類單位共用同一個總數，不各自建立容量池。
- V1 沒有技能直接增加可帶領數量，也沒有「可帶領數量 +1」裝備詞條。
- 現行技能組沒有魅力加成。
- 裝備可以在正式裝備屬性規格允許後提供魅力；有效魅力跨過門檻時，自然改變可帶領數量。
- 城主身分只提供使用士衛系統的資格，不額外增加可帶領數量。
- 硬上限為 5。

## 九、創角初始屬性

所有角色完全一致，不使用職業或種族初始模板：

```text
力量 10
敏捷 10
體質 10
智力 10
精神 10
魅力 10
```

固定初始總值為 60。

創角另給 **10 點自由配點**：

- 每點只能使其中一個基礎屬性 +1。
- 創角不得把任何屬性降到 10 以下來換取更多點數。
- 創角單一屬性最高 **18**。
- 10 點需在創角確認前分配完成，因此創角完成時六屬性總值固定為 **70**。
- `18` 只是創角上限，不是角色終身上限；51 級後升級配點與正式裝備修正可以使有效屬性高於 18。

這個配置保留明顯取捨：玩家可把一項拉到 18，但仍只剩 2 點分配其他屬性；也能把 5 點投入魅力直接跨到 15 的第二個可帶領單位門檻。

## 十、升級配點

第一版不採用「從 2 級開始每級 +1 主屬性」。若 2–50 級每級都給 1 點，50 級時會額外產生 49 點，會過早淹沒裝備、創角選擇與六屬性門檻。

正式規則：

```text
Lv 2–50：不獲得自由主屬性點
升到 Lv 51：獲得第 1 點
Lv 52 之後：每升 1 級再獲得 1 點
```

因此角色因等級已取得的升級主屬性點總數為：

```text
已取得升級主屬性點 = max(角色等級 - 50, 0)
```

配點規則：

- 每 1 點只能把六大基礎屬性其中一項 +1。
- 未使用點數可以保留，必須由 Server 持久化。
- Server 必須能由角色等級、已花費點數與未花費點數驗證總量，不接受 Client 宣告剩餘點數。
- 不做職業專用加點、不做隨機成長、不因裝備或技能額外產生「升級點數」。
- 51 級後可把基礎屬性配到 18 以上。
- 角色終身單一基礎屬性硬上限應與正式最高等級一起定案；最高等級尚未正式固定前，不在本文件自行發明第二個上限。
- 洗點／重置方式、費用與限制尚未定案；在正式設計前不得自行實作免費重置或付費道具。

## 十一、舊專案參考與星壘取捨

`li41/myriad-throne-server` 只作數值節奏參考：

- 舊創角使用職業專屬最低屬性，單項創角上限為 18；不同舊職業的初始總值約落在 59–71。Astrahold 不搬職業模板，而改為所有人 60 基礎 + 10 自由點 = 70，保留相近的初始數值尺度。
- 舊屬性分配入口會拒絕 51 級以下角色，因此「51 級才開始正式追加主屬性」保留其晚期成長節奏。
- 舊專案是否每一個 51 級後等級都產生 `BonusStats`，不能只從分配入口推出；Astrahold 在此明確自行定義為「升到 51 級起，每級固定取得 1 點」。
- 舊職業 HP／MP 的**數值尺度**保留作正式參考：Astrahold 收斂為 Lv.1 BaseMaxHP 15／BaseMaxMP 6、每級固定 +11 HP／+2 MP；舊職業模板、每級隨機值與職業倍率不搬入。體質／精神仍走 Astrahold 自己的 derived bonus。

## 十二、實作邊界

此規劃落地時，Server 至少需要權威擁有：

- 六大基礎屬性。
- 創角已分配結果。
- 51 級後已取得／已花費／未花費主屬性點的可驗證狀態。
- 裝備、被動與暫時修正後的有效屬性推導。
- 由角色等級推導的 BaseMaxHP／BaseMaxMP，以及由有效屬性、裝備、套裝、詞綴、被動與暫時效果聚合出的最終生命／魔力。
- 物理命中／閃避評分彙總、物理命中率擲骰與爆擊率計算。
- 魔法動作通過合法性後的必中語義；不得重新引入魔法命中評分。
- 配點 command 的合法性、持久化與重連一致性。

Network、資料庫、管理工具與 Client 都不得直接改 mutable gameplay world truth；正式 mutation 必須回到 Server owner path。
