# 星壘 — 遊戲內容與系統規劃

本文件記錄目前已討論確認的 gameplay / content truth 與仍待定案的空缺。無職業角色與 20 技能的完整規格以 [無職業技能系統規劃](無職業技能系統規劃.md) 為準。

任何武器、怪物、技能、掉落、商店、數值或取得方式，都不能因為 Server 已有能力就由 agent 自行補完。

## 一、內容設計原則

1. Server correctness 可以直接修；新內容數值與取得方式先定案再實作。
2. Gameplay feature 優先做 generic module，再由 archetype / stats / policy / loot table / AI config / respawn policy 擴充。
3. Client 不決定 damage、loot、equipment legality、AI、HP/MP、cooldown、skill result 或 persistence outcome。
4. 正式未來方向為 classless；不新增新的 class-gated gameplay。
5. 舊職業技能、ClassID、class resource 只保留為目前 runtime 遷移／regression evidence，不再視為未來內容規劃。

## 二、無職業角色與技能 V1

角色 Build：

```text
屬性配點 + 裝備 + 已學技能 + 實戰技能配置
```

所有角色最終可學全部正式技能；裝備原則上也不受職業限制。真正需要的 weapon / shield / slot requirement 應直接由 equipment / action semantics 表達。

### 實戰配置

```text
basic-attack
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 6 個自由戰鬥技能（從近戰／遠攻／法術共 12 招選）
```

六格可跨分類任意混搭。

### 20 技能

**通用**：瞬間移動術、日光術、防禦 Guard、治癒術。

**近戰**：重擊 Heavy Strike、連斬 Flurry、橫掃 Cleave、處決 Execute。

**遠攻**：穿透射擊 Piercing Shot、快速射擊 Rapid Shot、箭雨 Volley、牽制射擊 Pinning Shot。

**法術**：火焰彈 Fire Bolt、冰霜爆發 Frost Burst、隕星 Meteor、奧術長矛 Arcane Lance。

**輔助**：體魄強健（力量 +5，被動）、通暢氣脈（敏捷 +5，被動）、靈力凝聚（增加魔法攻擊，被動，數值待定）、加速術（主動 x1.3，作用項目／時間／CD 待定）。

日光術效果、Guard 數值、治癒量、傳送範圍、12 個戰鬥技能的傷害／CD／range／resource／scaling，以及技能學習方式都尚未定案，不從舊職業技能直接繼承。

## 三、第一批低階武器 v1

| 物品 | 小型傷害 | 大型傷害 | 額外傷害 | 命中修正 | 基本攻擊間隔 |
|---|---:|---:|---:|---:|---:|
| 民兵鐵劍 `item_militia_iron_sword` | 6–9 | 6–8 | 0 | 0 | 1.00s |
| 輕衛鐵劍 `item_light_guard_sword` | 5–8 | 5–7 | 0 | +2 | 0.85s |
| 鬥士鐵劍 `item_gladiator_iron_sword` | 7–10 | 6–9 | 0 | 0 | 1.10s |
| 民兵戰斧 `item_militia_battle_axe` | 5–8 | 8–12 | 0 | -1 | 1.15s |
| 鐵頭戰錘 `item_iron_war_mace` | 6–9 | 6–9 | +1 | +1 | 1.15s |

目前 entity-target `basic-attack` 會使用 authoritative 裝備武器傷害；Server 先驗證 target / range / LOS / protection 等 legality，再由 Server 決定 roll 與 final damage。CombatEvent、HP mutation、loot contribution 共用同一份 actual damage truth。

### 命中修正 v1

現行 Server 已啟用：

```text
HitChance = clamp(90 + accuracy_modifier * 2, 75, 98)
```

只套用於裝備本批 authored low-tier weapon 的 entity-target `basic-attack`。Server 擲 0..99；roll < HitChance 才命中。miss 不扣 HP，產生 authoritative miss outcome，且攻擊 cooldown 仍消耗。Client 不得自行擲命中。

## 四、第一批低階盾牌 v1

| 物品 | PhysicalDefense | BlockChance | BlockReduction | MagicReduction |
|---|---:|---:|---:|---:|
| 木鐵圓盾 `item_iron_rim_round_shield` | +3 | 8% | 25% | 0% |
| 守備盾 `item_guard_shield` | +4 | 10% | 30% | 0% |
| 方紋魔盾 `item_runed_square_shield` | +2 | 6% | 20% | 8% |

物理防禦公式：

```text
PhysicalMitigationRate = PhysicalDefense / (PhysicalDefense + 20)
```

Authoritative flow：

```text
合法傷害
-> DamageType / Blockable
-> authoritative OffHand
-> PhysicalDefense 或 MagicReduction
-> 明確 Blockable 才由 Server 擲一次 BlockChance
-> 成功才套 BlockReduction
-> 最後一次 rounding
-> 一般正傷害最低 1
-> final damage
-> HP / CombatEvent / contribution
```

現行 action semantics：

- `basic-attack`、`wolf-bite`：Physical + Blockable。
- `shatter-strike`：Physical + NotBlockable。
- `fireball`、`meteor-strike`：Magic + NotBlockable。
- v1 不看角色面向／攻擊角度。

低階盾現有資料為 `ClassPolicy=All`。未來 classless 方向不再新增 ClassID AllowList；裝備合法性收斂到 ownership、slot、hand conflict、equipment tag / requirement 等真正的物品條件。

## 五、低階裝備取得方式

目前上述 8 件低階裝備仍**沒有正式取得方式**：

- 無正式怪物掉落／掉率
- 無商店
- 無材料兌換
- 無任務
- 無製作
- 無初始裝備
- 無金幣價格

取得來源與經濟內容之後再逐項定案。

## 六、Monster body size

`EntityState.BodySize` 是 authoritative body-size truth。

- 不從 Client scale 推測。
- 不從舊 entity incarnation 繼承。
- 尚未定義的 monster archetype 不因 compatibility fallback 自動升格成正式 small / large 內容。

## 七、Encounter / threat

Threat v1 使用 Server-confirmed actual player damage 累加，stable `EntityID` 作 identity，最高 threat 決定 AI target；相同 threat 以較小 EntityID deterministic tie-break。

invalid/dead/disconnected/revive-protected/wrong-layer/leash/LOS target 會 prune；全部失效才 evade / return-home。Evade、defeat、despawn、respawn 都清 encounter threat；evade 亦清與怪物相關的 transient source-target combat resource，failed pull 不得污染下一場 encounter。

Threat 與 loot contribution 可共用 actual-damage fact，但不是同一張 table。

## 八、Transient status

Server 已有 generic transient status lifecycle：stable effect ID + EntityID、apply / refresh / half-open expiry / remove / entity clear，並在 player defeat / formal leave / monster incarnation lifecycle 清理。

既有 Fortify 是 class-era runtime/regression case；不再把 Oathguard 當未來職業設計。Slow、stun、poison、temporary shield、weapon enchant、resistance 等仍需對應新的正式技能／內容 contract 才能落地。

## 九、Ground drop / inventory / equipment

- Public monster ground drop 有 Server-owned bounded tick expiry。
- pickup / auto-loot / rollback / expiry 共用 authoritative lifecycle，不 double-mutate。
- defeated actor 不得 pickup、equip 或 unequip。
- inventory / equipment truth 只能由 authoritative owner path mutation。

若未來加入 durability、enchant、binding、tradable state 或 instance roll，drop / pickup / persistence / trade 必須完整保留同一 item instance state。

## 十、吸魔武器

歷史原型不是正式內容。已撤回固定 `+5 MP`、狼皮兌換與未經討論的取得方式。

只保留方向：不能對同一目標無限吸、應受目標 MP／可吸額度影響、吸取量由 Server 決定並可有隨機變化。完整公式尚未定案。

## 十一、Classless migration

現有 v27 runtime 仍包含 ClassID、class-gated action 與 class resource。這些不是未來設計，但在 persistence / Protocol / regression 安全遷移前不得直接刪除 production path。

施工方向：

1. 停止新增 class-gated gameplay。
2. 建立 authoritative attributes / learned skills / combat loadout。
3. 建立通用／輔助固定能力 + 6 格自由戰鬥技能。
4. 逐步以新的 20 技能取代舊職業 action；不直接搬舊數值。
5. 裝備 legality classless 化。
6. 最後處理 ClassID / class resource / persistence / Protocol migration。

## 十二、後續 roadmap

- Monster abilities：先有 generic range / LOS / cooldown / target / effect semantics，再配置具體怪物。
- Ground effects / hazards：Server 決定範圍、觸發、傷害、TTL、lifecycle。
- Economy：shop atomicity、warehouse、trade escrow、crash recovery / idempotency。
- Party：stable identity、loot policy、cooperative threat。
- Quest：kill / pickup / interact / enter-area authoritative objectives；reward exactly-once。
- 後期：pet、mail、private shop、auction、crafting、guild、war、siege、ranking、fishing、housing。

## 十三、參考 `myriad-throne-server`

可借鑑 mature invariant / tests：共用 damage resolution、equipment derived state、status lifecycle、threat consistency、transaction rollback、persistence correctness、action reentrancy、visibility / AOI。

不得照搬具體武器／技能／職業／怪物／掉落、舊 Protocol、session identity、Client gfx ID 或 Lua-first gameplay architecture。
