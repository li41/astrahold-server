# 星壘 — 遊戲內容與系統規劃

本文件記錄目前已討論確認的遊戲／內容事實，以及仍待定案的空缺。無職業角色與 20 技能的完整規格以 [無職業技能系統規劃](無職業技能系統規劃.md) 為準。

任何武器、怪物、技能、掉落、商店、數值或取得方式，都不能因為伺服器已有能力就由 agent 自行補完。

## 一、內容設計原則

1. 伺服器正確性可以直接修；新內容數值與取得方式先定案再實作。
2. 遊戲功能優先做成通用模組，再由原型（archetype）、數值（stats）、政策（policy）、掉落表（loot table）、AI 設定、重生政策擴充。
3. 客戶端不決定傷害、掉落、裝備合法性、AI、生命／魔力、冷卻時間、技能結果或持久化結果。
4. 正式未來方向為無職業制（classless）；不新增新的職業限定遊戲內容。
5. 舊職業技能與 `ClassID` 只保留為相容／迴歸驗證證據；既有 Resolve、Momentum、Hunt Momentum、Star Heat、Oath Seal 等穩定戰鬥資源 ID 可繼續被動作使用，但不是固定職業身分。資源定義由通用 action-resource authority 擁有，舊 class vocabulary 只留在必要相容邊界。

## 二、無職業角色與技能第一版

角色配裝流派（Build）：

```text
屬性配點 + 裝備 + 已學技能 + 實戰技能配置
```

所有角色最終可學全部正式技能；裝備原則上也不受職業限制。真正需要的武器／盾牌／裝備欄位需求，應直接由裝備／動作語義表達。

### 實戰配置

```text
基本攻擊（basic-attack）
+ 全部 4 個通用技能
+ 全部 4 個輔助技能
+ 6 個自由戰鬥技能（從近戰／遠攻／法術共 12 招選）
```

六格可跨分類任意混搭。

### 20 技能

**通用**：瞬間移動術、日光術、防禦（Guard）、治癒術。

**近戰**：重擊（Heavy Strike）、連斬（Flurry）、橫掃（Cleave）、處決（Execute）。

**遠攻**：穿透射擊（Piercing Shot）、快速射擊（Rapid Shot）、箭雨（Volley）、牽制射擊（Pinning Shot）。

**法術**：火焰彈（Fire Bolt）、冰霜爆發（Frost Burst）、隕星（Meteor）、奧術長矛（Arcane Lance）。

**輔助**：體魄強健（力量 +5，被動）、通暢氣脈（敏捷 +5，被動）、靈力凝聚（增加魔法攻擊，被動，數值待定）、加速術（主動 ×1.3，作用項目／時間／冷卻時間待定）。

日光術效果、防禦數值、治癒量、傳送範圍、12 個戰鬥技能的傷害／冷卻時間／距離／資源／成長係數，以及技能學習方式都尚未定案，不從舊職業技能直接繼承。

| 民兵鐵劍 `item_militia_iron_sword` | 6–9 | 6–8 | 0 | 0 |
| 輕衛鐵劍 `item_light_guard_sword` | 5–8 | 5–7 | 0 | +2 |
| 鬥士鐵劍 `item_gladiator_iron_sword` | 7–10 | 6–9 | 0 | 0 |

目前對實體目標的 `basic-attack` 會使用權威裝備武器傷害；伺服器先驗證目標、距離、視線（LOS）、保護狀態等合法性，再由伺服器決定擲骰與最終傷害。`CombatEvent`、生命變更、掉落貢獻共用同一份實際傷害事實。

### 基礎攻速規則

正式規則：

```text
WeaponType -> BasicAttackIntervalMS
```

- 基礎攻速是**武器類型**的權威資料，不是單件 `ItemArchetype` 的可覆寫屬性。
- 相同 `WeaponType` 的所有武器，基礎攻擊間隔必須完全一致；品質、傷害、命中修正可以不同，但不得藉由單件物品改變基礎攻速。
- per-item `BasicAttackIntervalMS` 已自 `equipmentcatalog.Weapon` 退役，strict loader 會拒絕舊 `basic_attack_interval_ms` 欄位。
- 18 類 V1 正式基礎攻擊間隔已定案並實作：空手 600ms；17 個裝備武器類型由 `WeaponType` table authored。完整表見 [武器攻速](武器攻速.md)。
- 現有低階三把單手劍使用 `one_hand_sword = 900ms`，民兵戰斧使用 `one_hand_axe = 1050ms`，鐵頭戰錘現行 `mace = 1050ms`。
- 先前低階物品表中的 0.85／1.00／1.10／1.15 秒單件攻速與 0.5 秒暫時 fallback 均已被正式 V1 設定 supersede，不得重新引入。
- 未來裝備、增益或狀態若提供攻速修正，由 Server 在權威戰鬥路徑算出最終有效間隔；Client 只消費 Server 的 authoritative `cooldown_ready_tick` 做動畫呈現。
- Client 不得從動畫長度、模型、武器外觀分類、本地 WeaponType 表或本地計時器推導 gameplay 攻速。

Server issue #183 已完成關閉；後續 Client 動畫呈現整合由 `li41/astrahold-client-three.js#23` 追蹤，不改變 Server gameplay authority。

### 物理命中／閃避第一版

現行低階武器 `basic-attack` 原始碼仍使用舊公式：

```text
HitChance = clamp(90 + accuracy_modifier * 2, 75, 98)
```

這是目前低階施工期相容行為，不再是完整角色戰鬥公式的最終設計。正式角色屬性／裝備詞綴接入時，應由以下統一公式取代，不得兩套重複疊加：

```text
總物理命中值
= 敏捷來源物理命中值
+ 武器命中修正
+ 裝備物理命中詞綴
+ Server 認可的其他修正

總閃避值
= 敏捷來源閃避值
+ 裝備閃避詞綴
+ Server 認可的其他修正

物理命中率
= clamp(90% + (攻擊者總物理命中值 - 目標總閃避值) × 0.5 個百分點, 75%, 98%)
```

- 每 1 點淨物理命中評分優勢等於 0.5 個百分點命中率。
- 最低物理命中率 75%，最高 98%。
- Server 擲骰並決定命中／未命中；Client 只能呈現結果。

### 魔法必中第一版

V1 魔法採**必中**。魔法動作通過 Server 的目標、距離、視線、資源、冷卻、免疫／合法性等檢查後，不再進行隨機命中／未命中擲骰。

必中不代表繞過魔法防禦、魔法減傷、免疫或技能本身其他合法性條件。V1 因此不建立「魔法命中值」評分，也不提供魔法命中裝備詞綴。

### 爆擊第一版

對正式允許爆擊的動作：

```text
最終爆擊率
= min(30%, 5% + 屬性爆擊加成 + 爆擊值 × 0.5 個百分點)

爆擊傷害
= 爆擊前傷害 × 1.5
```

- 基礎爆擊率為 5%。
- 每 1 點爆擊值提供 0.5 個百分點爆擊率。
- 敏捷 40 起的屬性來源爆擊加成依 [角色屬性與成長規劃](角色屬性與成長規劃.md) 計算。
- 最終爆擊率硬上限為 30%。
- 第一版爆擊傷害倍率固定為 **1.5 倍**，沒有爆擊傷害詞綴。
- 基本攻擊、單次直接物理傷害與單次直接魔法傷害可爆擊。
- 持續傷害、地面持續傷害、中毒／燃燒等週期傷害與治療不可爆擊。
- 範圍攻擊命中多個目標時，每個實際目標傷害實例獨立擲爆擊；一次爆擊不得讓全部目標一起爆擊。
- 多段攻擊的每一段實際傷害獨立擲爆擊；一次爆擊不得讓後續段數自動爆擊。
- 物理攻擊先通過物理命中判定，命中後才有爆擊擲骰；未命中不再擲爆擊。
- 魔法通過合法性後必中，再對允許爆擊的直接魔法傷害獨立擲爆擊。
- 具體技能仍應由 Server 動作定義明確標示是否屬於可爆擊的直接傷害，不由 Client 或動畫推導。

### 傷害結算順序第一版

正式傷害順序：

```text
合法性／命中判定
-> 武器或技能基礎傷害
-> 力量／敏捷／智力等屬性加成
-> 物理傷害／魔法威力等裝備平面加成
-> 若允許且擲中爆擊，乘 1.5
-> 對應防禦／減傷階段
-> 盾牌等額外防禦效果
-> 最後一次取整
-> 一般正傷害最低 1
-> 最終傷害
-> HP／CombatEvent／貢獻
```

爆擊發生在防禦／減傷之前。物理防禦已具有正式換算公式；魔法防禦值與既有盾牌魔法減傷百分比如何分層換算仍需下一步正式定案，但不得改變「爆擊先於防禦」的順序。

## 四、第一批低階盾牌第一版

| 物品 | 物理防禦 `PhysicalDefense` | 格擋機率 `BlockChance` | 格擋減傷 `BlockReduction` | 魔法減傷 `MagicReduction` |
|---|---:|---:|---:|---:|
| 木鐵圓盾 `item_iron_rim_round_shield` | +3 | 8% | 25% | 0% |
| 守備盾 `item_guard_shield` | +4 | 10% | 30% | 0% |
| 方紋魔盾 `item_runed_square_shield` | +2 | 6% | 20% | 8% |

物理防禦公式：

```text
PhysicalMitigationRate = PhysicalDefense / (PhysicalDefense + 20)
```

權威結算流程以本文件「傷害結算順序第一版」為總順序；盾牌效果屬於防禦階段後段：

```text
合法傷害
-> 對應防禦／減傷階段
-> 只有明確可格擋的物理傷害才由 Server 擲一次格擋機率（BlockChance）
-> 成功才套用格擋減傷（BlockReduction）
-> 魔法傷害可套用盾牌既有 MagicReduction；與魔法防禦值的正式先後／換算下一步定案
-> 最後一次取整
-> 一般正傷害最低 1
-> 最終傷害
```

現行動作語義：

- `basic-attack`、`wolf-bite`：物理（Physical）+ 可格擋（Blockable）。
- `shatter-strike`：物理 + 不可格擋（NotBlockable）。
- `fireball`、`meteor-strike`：魔法（Magic）+ 不可格擋。
- 第一版不看角色面向／攻擊角度。

低階盾資料已不再帶固定職業 `ClassPolicy`。無職業方向不再新增 `ClassID AllowList`；裝備合法性收斂到持有權、裝備欄位、手持衝突、裝備標籤／需求等真正的物品條件。

## 五、低階裝備取得方式

目前上述 8 件低階裝備仍**沒有正式取得方式**：

- 無正式怪物掉落／掉率
- 無商店
- 無材料兌換
- 無任務
- 無製作
- 無初始裝備
- 無金幣價格

取得來源與經濟內容之後再逐項定案。

### 裝備階級與隨機附加屬性第一版

隨機附加屬性的**條數**已正式定案：

| 裝備階級 | 隨機附加屬性條數 |
|---|---:|
| 低階 | 0 |
| 中階 | 1 |
| 高階 | 2 |

固定規則：

- 低階裝備只有該 `ItemArchetype` 本身的固定基礎數值／固定性質，**不產生任何隨機附加屬性**。
- 中階裝備建立為物品實例時，由 Server 產生恰好 1 條隨機附加屬性。
- 高階裝備建立為物品實例時，由 Server 產生恰好 2 條隨機附加屬性。
- 高階裝備兩條詞綴不得使用相同 `AffixID`；第二條必須從排除第一條後的合法池抽取。
- 隨機屬性的合法池、實際數值與擲骰結果都屬於 Server gameplay truth；Client 只能呈現結果。
- 隨機結果必須跟著同一物品實例持久化；掉落、撿取、背包、裝備、交易與重新登入不得因重新載入而重擲。
- 若未來加入重鑄／洗詞綴，必須另有明確 Server 權威動作與成本規則；在該系統正式定案前，既有物品不得自行重擲。
- 基礎攻速不屬於隨機附加屬性；相同 `WeaponType` 仍必須共享同一正式基礎攻速。
- 「可帶領數量 +1」不作為詞綴；魅力詞綴只能先改變有效魅力，再依正式魅力門檻推導可帶領數量。

第一版正式詞綴池共 **15 種**，只允許以下詞綴：

- 六大屬性：力量、敏捷、智力、體質、精神、魅力。
- 攻擊向：物理命中值、爆擊值、物理傷害、魔法威力。
- 防禦／資源向：閃避值、最大生命、最大魔力、物理防禦、魔法防禦。

V1 魔法必中，因此先前規劃中的「魔法命中值」已移除，不再是正式詞綴。

第一版隨機詞綴池**不包含**攻速、冷卻縮減、吸血／吸魔、經驗／掉寶率、技能等級、命中觸發特效、直接增加可帶領數量、元素傷害、穿透、爆擊傷害與盾牌格擋詞綴。即使底層系統日後具備相關能力，也不得自行把這些效果加入第一版詞綴池；任何新增詞綴都必須經過明確的後續版本定案。

#### 第一版裝備類型合法詞綴池

目前正式裝備資料實際存在主手武器與副手盾牌，因此第一版先只定義這兩類，不先發明尚未存在的防具／飾品欄位。

**主手武器共 10 種合法詞綴：**

- 六大屬性：力量、敏捷、智力、體質、精神、魅力。
- 攻擊向：物理命中值、爆擊值、物理傷害、魔法威力。

主手武器不骰閃避值、最大生命、最大魔力、物理防禦、魔法防禦。

**副手盾牌共 11 種合法詞綴：**

- 六大屬性：力量、敏捷、智力、體質、精神、魅力。
- 防禦／資源向：閃避值、最大生命、最大魔力、物理防禦、魔法防禦。

副手盾牌不骰物理命中值、爆擊值、物理傷害、魔法威力。

同一合法池中的詞綴種類 V1 使用等機率，不另外建立「爆擊比較稀有」等隱藏種類權重；真正的稀有度主要由後續強度擲骰決定。

#### 詞綴強度擲骰第一版

Server 先決定合法詞綴種類，再對每一條已選出的詞綴**獨立擲出強度**。裝備階級決定可出現的強度與機率：

| 裝備階級 | 詞綴強度 | 機率 |
|---|---:|---:|
| 中階 | +1 | 90% |
| 中階 | +2 | 10% |
| 高階 | +1 | 90% |
| 高階 | +2 | 7% |
| 高階 | +3 | 2.5% |
| 高階 | +4 | 0.45% |
| 高階 | +5 | 0.05% |

固定規則：

- 中階單條詞綴只可能出現 +1 或 +2；高階單條詞綴可能出現 +1 至 +5。
- 高階裝備的兩條詞綴各自獨立擲強度，不共用同一次強度結果。
- 強度擲骰由 Server 在物品實例建立時完成，結果與詞綴種類一起持久化；重新載入不得重擲。
- `+1` 至 `+5` 是詞綴強度層級。
- 六大屬性詞綴依強度直接對應屬性 +1 至 +5。
- 物理命中值、爆擊值、閃避值依強度直接對應評分 +1 至 +5；這些評分不是直接百分比，依本文件正式公式換算。
- 物理傷害、魔法威力、物理防禦、魔法防禦依強度直接對應平面數值 +1、+2、+3、+4、+5，不是百分比。
- 最大生命依強度對應 +20、+40、+60、+80、+100。
- 最大魔力依強度對應 +10、+20、+30、+40、+50。

對照表：

| 詞綴 | +1 | +2 | +3 | +4 | +5 |
|---|---:|---:|---:|---:|---:|
| 六大屬性 | +1 | +2 | +3 | +4 | +5 |
| 物理命中值 | +1 | +2 | +3 | +4 | +5 |
| 爆擊值 | +1 | +2 | +3 | +4 | +5 |
| 閃避值 | +1 | +2 | +3 | +4 | +5 |
| 物理傷害 | +1 | +2 | +3 | +4 | +5 |
| 魔法威力 | +1 | +2 | +3 | +4 | +5 |
| 物理防禦 | +1 | +2 | +3 | +4 | +5 |
| 魔法防禦 | +1 | +2 | +3 | +4 | +5 |
| 最大生命 | +20 | +40 | +60 | +80 | +100 |
| 最大魔力 | +10 | +20 | +30 | +40 | +50 |

目前這套詞綴的種類、條數、強度機率、不可重複規則與數值映射均已定案。下一個仍需補齊的戰鬥規則是：**魔法防禦值如何換算減傷，以及它與盾牌既有 `MagicReduction` 百分比如何分層。**

## 六、怪物體型（Monster Body Size）

`EntityState.BodySize` 是權威怪物體型事實。

- 不從客戶端縮放比例（scale）推測。
- 不從舊實體世代（entity incarnation）繼承。
- 尚未定義的怪物原型不因相容回退（compatibility fallback）自動升格成正式小型／大型內容。

## 七、遭遇／仇恨（Encounter / Threat）

仇恨第一版使用伺服器確認的玩家實際傷害累加，以穩定 `EntityID` 作身分，最高仇恨決定 AI 目標；相同仇恨以較小 `EntityID` 作確定性同值判定。

無效、死亡、斷線、重生保護、錯誤層、超出牽制範圍、視線失效的目標會被清除；全部失效才脫戰／回家。脫戰、敗北、消失、重生都清除遭遇仇恨；脫戰也會清除與怪物相關的暫時性來源－目標戰鬥資源，失敗拉怪不得污染下一場遭遇。

仇恨與掉落貢獻可以共用實際傷害事實，但不是同一張資料表。

## 八、暫時狀態（Transient Status）

伺服器已有通用暫時狀態生命週期：穩定效果 ID + `EntityID`、套用／刷新／半開區間到期／移除／實體清理，並在玩家敗北／正式離開／怪物實體世代生命週期清理。

既有 Fortify 是職業制時期的執行期／迴歸驗證案例；不再把 Oathguard 當未來職業設計。緩速（slow）、暈眩（stun）、中毒（poison）、暫時護盾、武器附魔、抗性等仍需對應新的正式技能／內容契約才可落地。

## 九、地面掉落／背包／裝備

- 公開怪物地面掉落有伺服器權威且有界限的 Tick 到期機制。
- 撿取／自動拾取／回滾／到期共用權威生命週期，不得重複修改。

- 背包／裝備事實只能由權威擁有者路徑修改。

若未來加入耐久、附魔、綁定、可交易狀態或實例隨機屬性，掉落／撿取／持久化／交易必須完整保留同一物品實例狀態。

## 十、吸魔武器

歷史原型不是正式內容。已撤回固定 `+5 MP`、狼皮兌換與未經討論的取得方式。

只保留方向：不能對同一目標無限吸、應受目標魔力／可吸額度影響、吸取量由伺服器決定並可有隨機變化。完整公式尚未定案。

## 十一、無職業制遷移

production runtime state 已不再由 `ClassID` 決定角色身分，durable schema 也已完成 classless migration。Server source-side fixed-class restore／resource compatibility 已收斂完成；現行技術債主要剩下：

- Protocol v27 message type 9／115／116 與 type117 `CharacterClassResourceState` 相容 lane，以及 `wrong_class` compatibility vocabulary。
- formal Client 仍存在 initial-class intent、class state/result/resource store/UI consumer；Client #21 的 read-only consumer audit 已完成，breaking removal 現在被 Client migration 阻塞，而不是等待 audit。
- 必要 legacy persistence migration／E2E fixture 的 ClassID vocabulary；歷史 `class_id` 只在 decoder 驗證後丟棄，不恢復成 gameplay profession truth。
- `internal/classresource`、`CharacterRestore.LegacyRuntimeClassID`、fixed-class resource lookup 與 production class-named resource ownership已退役，不再列為待清項目。

施工方向：

1. 停止新增職業限定遊戲內容。
2. 建立伺服器權威角色屬性、已學技能、戰鬥技能配置。
3. 建立通用／輔助固定能力 + 6 格自由戰鬥技能。
4. 逐步以新的 20 技能取代舊職業動作；不直接搬舊數值。
5. 將裝備合法性無職業化。
6. 維持 Server 內部 generic action/resource ownership；不為相容 wire 重新建立 class authority。
7. 等 Client #21 完成實際 consumer removal／migration 並回報安全 breaking boundary，再移除或重編 v27 class compatibility wire；Server 不先破壞正式 Client。
