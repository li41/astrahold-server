# 星壘 — 箭矢規劃

本文件定義正式 Server 的弓箭彈藥規則。Server 是唯一 gameplay authority；Client 可以播放拉弓、放箭動畫與顯示箭矢數量，但不得自行決定是否真的射出箭、消耗幾支箭、命中、傷害或冷卻。

## 一、核心規則

第一版固定：

- 弓的普通攻擊需要箭。
- 每次真正成立的射擊消耗 **1 支箭**。
- 射出去但未命中，仍消耗 **1 支箭**。
- 沒有箭時，Server 拒絕射擊：不產生權威射擊事件、不產生傷害、不產生權威投射物，也不啟動該次攻擊冷卻。
- 沒有箭時，Client 仍可播放本地拉弓／放箭動畫作為操作回饋，但不得自行生成 gameplay 結果。
- 目標非法、超出射程、冷卻中等未成立的攻擊不消耗箭。
- 箭是背包中的可堆疊消耗品，不是第八個裝備欄位；正式七欄裝備契約不變。
- 第一版只有 `bow` 使用箭；`crossbow` 不共用箭，未來若需要彈藥則另規劃弩矢。
- 投石類武器不使用箭。

## 二、第一版三種箭

| 階級 | 穩定 ItemArchetypeID | 中文名稱 | 主材質 | 箭矢傷害 | 單支負重 |
|---|---|---|---|---:|---:|
| 低階 | `item_low_arrow` | 木箭 | 木 | 6–8 | 0 |
| 中階 | `item_mid_arrow` | 鋼箭 | 鋼 | 8–11 | 0 |
| 高階 | `item_high_arrow` | 星鋼箭 | 星鋼 | 10–15 | 0 |

目前背包負重使用整數粒度；如果每支箭至少計 1 重量，少量箭就會不合理地吃滿角色負重。因此第一版三種箭皆不計負重，但仍佔用一個背包堆疊項目。未來若負重系統改成更細的單位，再重新定義箭矢重量。

第一版不新增銀箭。現行「銀質主手武器對不死系 +20%」規則只適用於正式主手銀武器，不自動延伸到箭矢。

## 三、弓本體與箭矢共同決定傷害

弓本體攻擊降低，箭矢本身提供另一部分攻擊力。

普通弓箭攻擊的基礎武器傷害區間：

```text
最小傷害 = 弓最小傷害 + 箭最小傷害
最大傷害 = 弓最大傷害 + 箭最大傷害
```

Server 在合併後的完整區間內只擲 **一次** 隨機傷害，不分別擲弓與箭後再相加，避免改變傷害分布。

三階正式數值：

| 階級 | 弓本體 | 同階箭 | 合計區間 |
|---|---:|---:|---:|
| 低階 | 2–3 | 6–8 | **8–11** |
| 中階 | 3–4 | 8–11 | **11–15** |
| 高階 | 4–5 | 10–15 | **14–20** |

因此這次調整是把原本弓本體的完整傷害拆成「弓＋箭」，同階搭配下維持既有三階總輸出，不額外強化也不額外削弱弓系基礎傷害。

現行三把 production 弓：

- `item_hunter_shortbow`：2–3
- `item_mid_bow`：3–4
- `item_high_bow`：4–5

## 四、箭矢選擇

第一版不新增額外選箭介面或新的 Protocol 欄位。

玩家背包同時存在多種箭時，Server 固定依下列順序消耗：

```text
木箭
-> 鋼箭
-> 星鋼箭
```

也就是優先使用較低階箭，避免玩家攜帶普通箭時默默消耗稀有高階箭。

未來若產品需要玩家主動指定箭種，再新增明確的 Server-owned 選箭狀態與 Client 消費契約；不得以 Client 本地選單直接決定實際消耗箭種。

## 五、一次射擊的權威流程

```text
Client 發出普通攻擊意圖
-> Server 驗證角色／目標／冷卻／射程
-> Server 確認主手是否為弓
-> Server 確認背包是否有可用箭
-> 沒箭：拒絕，不扣箭、不啟動這次攻擊冷卻、不產生傷害
-> 有箭：進入實際射擊
-> Server 擲命中
   -> 未命中：扣 1 支箭，產生 miss 結果
   -> 命中：弓傷害 + 該支箭傷害，扣 1 支箭
-> 後續屬性加成／暴擊／減傷／格擋沿用既有 Server 權威傷害流程
```

箭矢消耗必須修改正式角色背包 truth，並透過既有 inventory snapshot／持久化路徑保存；不得只在 Client 畫面扣數量。

## 六、與現行裝備總數的關係

目前 **107 件** 指的是可裝備的 equipment archetype：

- 53 武器
- 9 盾牌
- 45 防具

三種箭是獨立的可堆疊消耗品，不計入上述 107 件可裝備裝備總數，也不新增裝備欄位。

## 七、目前未定內容

以下不因箭矢 V1 自動決定：

- 怪物掉箭的掉落表與掉率。
- 商店是否販售、價格多少。
- 任務獎勵數量。
- 製作配方與材料成本。
- 未來銀箭、特殊箭、屬性箭的效果。
- 弩矢系統。
- 玩家主動指定箭種的介面與契約。

這些內容必須在產品規則正式決定後，再接入既有 Server authority，不得由 Client 或單一資料表自行創造第二套 gameplay truth。
